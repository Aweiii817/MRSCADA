## 开篇：预备知识——第五阶段的四个核心概念

### 1. 什么是性能优化？为什么"先测量，再优化"？

软件性能优化最大的误区是"凭感觉优化"。程序员直觉上认为"这里慢了"，然后花三天优化一段代码，结果发现真正的瓶颈在另一个地方。

**正确的方法论是三步走：**

```
第一步：测量（Profiling）
    ↓ 找到真正的瓶颈
第二步：优化（Optimize）
    ↓ 只改瓶颈，不碰其他
第三步：验证（Verify）
    ↓ 测量优化前后，确认真的变快了
```

**怎么测量？** 最简单的方法是 Qt 的 `QElapsedTimer`：

```cpp
QElapsedTimer timer;
timer.start();

// ... 执行要测量的代码 ...

qint64 elapsed_ms = timer.elapsed();
LOG_INFO("耗时: {} ms", elapsed_ms);
```

更专业的工具：Visual Studio 性能探查器、perf（Linux）、Valgrind（内存）。

**本阶段要优化的已知瓶颈：**

| 瓶颈 | 现象 | 优化方向 |
|------|------|----------|
| 趋势曲线数据量过大 | 画 10 万点曲线卡顿 | 降采样（LTTB 算法） |
| 数据表格整表刷新 | 200 行每 100ms 全刷，CPU 高 | 只刷新变化的单元格 |
| RTDB 值拷贝 | 每次 getTagValue 都拷贝结构体 | 减少拷贝、move 语义 |
| 字符串拼接 | 大量 + 号拼接 QString | QStringBuilder 优化 |

### 2. 什么是"内存占用"优化？C++ 的内存问题有哪些？

C++ 的内存问题分两类：

**内存泄漏（Memory Leak）**：分配了内存忘记释放。程序越跑越占内存，最终崩溃。
- 传统 `new` 不 `delete` 会泄漏
- 解决：用智能指针（`unique_ptr`/`shared_ptr`）+ RAII，本项目的代码已经这么做了

**内存碎片 / 频繁分配**：反复分配释放小块内存，导致性能下降。
- 解决：预分配（`reserve`）、复用缓冲区、对象池

**Qt 特有的内存管理**：Qt 对象树会自动释放子对象，但有几个坑：
- 用 `new` 创建控件但没指定 parent 且没 delete → 泄漏
- 跨线程使用 QObject → 崩溃
- QObject 的 parent 在子类销毁时自动 delete，但 `deleteLater` 的时机要理解

### 3. 什么是代码审查？为什么要做？

代码审查（Code Review）= 让另一个人（或你自己换角色）逐行检查代码，找出：
- **Bug**：逻辑错误、边界条件遗漏
- **可维护性问题**：命名混乱、重复代码、魔法数字
- **安全隐患**：SQL 注入、缓冲区溢出、竞态条件

即使没有同事，也可以用"换角色"的方式自查：假设自己是接手这段代码的新人，能看懂吗？哪里会踩坑？

**本阶段提供一份审查清单**，你照着逐项检查自己的代码。

### 4. 什么是软件发布？windeployqt 是干什么的？

你写的程序在自己电脑上能跑，是因为你的电脑装了 Qt 的 DLL（动态链接库）。但用户电脑上没装 Qt，所以程序拷贝过去会报"缺少 Qt6Core.dll"之类的错。

**windeployqt** 是 Qt 自带的发布工具，它做两件事：
1. 分析你的 .exe 依赖哪些 Qt 的 DLL
2. 把这些 DLL 复制到 .exe 所在目录

运行后，整个目录（exe + dll + 资源）就是一个完整的发布包，拷到任何 Windows 电脑都能运行。

## 第一章：补齐单元测试

### 1.0 先搞清楚"测试什么、不测试什么"

前几阶段已经写了 TagManager、RingBuffer、SimReactor、HistoryDB 的测试。本阶段补齐剩下几个关键模块。

**测试的优先级（从高到低）：**

```
1. 纯逻辑、容易出错的计算 → 必须测
   RingBuffer 溢出覆盖、量程转换、报警状态机

2. 数据解析、边界条件 → 应该测
   JSON 解析、Modbus 地址映射、配置读写

3. 线程安全 → 重点测（难复现的 bug 最危险）
   RingBuffer 并发读写

4. UI 交互 → 少测（成本高、收益低）
   控件显示逻辑，通常用人工验证
```

**为什么要测线程安全？** 数据竞争类的 bug 是最难查的——它可能运行几百次才偶然崩一次，而且崩溃点往往不在真正出错的地方。写一个并发测试，让多线程反复读写，能提前暴露这类问题。

### 1.1 写 RingBuffer 线程安全测试

**文件路径：** `D:\QtProject\UCS\tests\test_ring_buffer_thread.cpp`

```cpp
// ============================================================
// RingBuffer 线程安全测试
//
// 用多线程反复并发读写，验证互斥锁的正确性。
// 如果锁没加好，这个测试会在某次运行时崩溃或数据错乱。
// ============================================================
#include <gtest/gtest.h>
#include <thread>
#include <atomic>
#include <vector>
#include "core/rtdb/RingBuffer.h"

// 测试：多线程并发 push 不崩溃、不丢失数据
TEST(RingBufferThreadTest, ConcurrentPush)
{
    const int thread_count = 4;          // 4 个写线程
    const int writes_per_thread = 1000;  // 每个线程写 1000 次
    const int capacity = 500;            // 缓冲区容量

    RingBuffer<int> buf(capacity);

    // 🎯 每个线程写入自己区间的值，这样能验证有没有串数据
    // 线程 0 写 0-999，线程 1 写 1000-1999，以此类推
    std::vector<std::thread> threads;
    for (int t = 0; t < thread_count; ++t) {
        threads.emplace_back([&buf, t, writes_per_thread]() {
            int base = t * writes_per_thread;
            for (int i = 0; i < writes_per_thread; ++i) {
                buf.push(base + i);
            }
        });
    }

    // 等待所有线程完成
    for (auto& th : threads) {
        th.join();
    }

    // 验证：size 应该等于容量（写满了，旧数据被覆盖）
    EXPECT_EQ(buf.size(), static_cast<size_t>(capacity));

    // 验证：读取的数据都在合法范围内（0 到 4*1000-1）
    auto data = buf.readAll();
    for (int val : data) {
        EXPECT_GE(val, 0);
        EXPECT_LT(val, thread_count * writes_per_thread);
    }
}

// 测试：一个线程写、一个线程读，并发不崩溃
TEST(RingBufferThreadTest, ConcurrentReadWrite)
{
    RingBuffer<int> buf(1000);
    std::atomic<bool> stop{false};

    // 写线程：持续写入
    std::thread writer([&buf, &stop]() {
        int i = 0;
        while (!stop.load()) {
            buf.push(i++);
        }
    });

    // 读线程：持续读取
    std::thread reader([&buf, &stop]() {
        while (!stop.load()) {
            auto data = buf.readAll();
            (void)data;   // 读取结果暂时不用
            int latest = buf.latest();
            (void)latest;
        }
    });

    // 运行 500ms 后停止
    std::this_thread::sleep_for(std::chrono::milliseconds(500));
    stop.store(true);

    writer.join();
    reader.join();

    // 能走到这里说明没有死锁、没有崩溃
    SUCCEED();
}
```

**要点说明：**
- `std::atomic<bool>` 是原子布尔变量，多线程读写安全，用来做停止标志
- 两个测试都用 `join()` 等待线程结束，确保测试线程正常退出

### 2.2 写 ThemeManager

**文件路径：** `D:\QtProject\UCS\src\common\ThemeManager.h`

```cpp
// ============================================================
// ThemeManager.h — 主题管理器
//
// 管理全局主题（亮色/暗色），提供运行时切换和持久化。
//
// 为什么单独一个类？
//   主题切换涉及"读 QSS 文件 + 应用到全局 + 保存选择"，
//   分散在各处会导致逻辑重复。集中管理更清晰。
// ============================================================
#pragma once

#include <QString>

/// @brief 主题类型
enum class Theme
{
    DARK,   // 暗色（默认，监控室长期值守）
    LIGHT   // 亮色（白天光线强）
};

class ThemeManager
{
public:
    static ThemeManager& instance();

    /// @brief 初始化（读取上次保存的主题并应用）
    void initialize();

    /// @brief 获取当前主题
    Theme currentTheme() const;

    /// @brief 切换主题并持久化
    /// @param theme 目标主题
    void setTheme(Theme theme);

    /// @brief 获取主题名称（中文，显示用）
    static QString themeName(Theme theme);

private:
    ThemeManager() = default;

    /// @brief 从资源读取 QSS 并应用到全局
    void applyTheme(Theme theme);

    /// @brief 从 QSettings 读取上次保存的主题
    Theme loadSavedTheme() const;

    /// @brief 保存当前主题到 QSettings
    void saveTheme(Theme theme);

    Theme m_current = Theme::DARK;
};
```

**文件路径：** `D:\QtProject\UCS\src\common\ThemeManager.cpp`

```cpp
// ============================================================
// ThemeManager.cpp — 主题管理器实现
// ============================================================
#include "ThemeManager.h"
#include "ConfigManager.h"
#include "Logger.h"
#include <QApplication>
#include <QFile>

ThemeManager& ThemeManager::instance()
{
    static ThemeManager inst;
    return inst;
}

void ThemeManager::initialize()
{
    Theme saved = loadSavedTheme();
    applyTheme(saved);
    LOG_INFO("ThemeManager: applied theme '{}'",
             themeName(saved).toStdString());
}

Theme ThemeManager::currentTheme() const
{
    return m_current;
}

void ThemeManager::setTheme(Theme theme)
{
    if (m_current == theme) return;

    applyTheme(theme);
    saveTheme(theme);
    LOG_INFO("ThemeManager: switched to '{}'",
             themeName(theme).toStdString());
}

QString ThemeManager::themeName(Theme theme)
{
    return (theme == Theme::DARK) ? "暗色" : "亮色";
}

void ThemeManager::applyTheme(Theme theme)
{

        ? ":/styles/dark_theme.qss"
        : ":/styles/light_theme.qss";

        style_file.close();
    } else {
        LOG_ERROR("ThemeManager: cannot load {}", qss_path.toStdString());

}
```

### 3.1 优化趋势曲线：LTTB 降采样

**问题：** 历史趋势查询可能返回几万到几十万个点，全部塞进 `QLineSeries` 会让图表卡死。

**解决：LTTB（Largest Triangle Three Buckets）降采样算法。**

LTTB 是专为时间序列可视化设计的降采样算法，核心思想：把数据分成若干"桶"，每个桶保留一个点，这个点是"最能代表曲线形状"的点（通过三角形面积计算）。

```
原始 10000 个点  →  LTTB 降采样  →  1000 个点（保留趋势形状）
```

```cpp
// ============================================================
// LTTB 降采样算法（放在一个工具文件里，如 Utility 或独立头文件）
//
// 用途：把大量数据点压缩到可视数量，同时保留曲线形状。
// 时间复杂度 O(n)，非常适合实时处理。
// ============================================================
#include <QVector>
#include <QPointF>
#include <cmath>

/// @brief LTTB 降采样
/// @param data 原始数据点（按 X 升序）
/// @param threshold 目标点数（如 1000）
/// @return 降采样后的点
inline QVector<QPointF> lttbDownsample(const QVector<QPointF>& data,
                                        int threshold)
{
    if (data.size() <= threshold || threshold < 3) {
        return data;   // 数据量不够，不需要降采样
    }

    QVector<QPointF> sampled;
    sampled.reserve(threshold);

    int data_count = data.size();

    // 🎯 桶的大小：每桶约 data_count/threshold 个点
    // 首点和尾点一定保留（保证曲线范围完整）
    double bucket_size = static_cast<double>(data_count - 2)
                       / static_cast<double>(threshold - 2);

    sampled.push_back(data.first());   // 保留第一个点

    // 遍历中间的桶，每个桶选一个"代表点"
    int prev_index = 0;   // 上一个已选点的索引
    for (int i = 0; i < threshold - 2; ++i) {
        // 当前桶的起止索引
        int bucket_start = static_cast<int>((i + 1) * bucket_size) + 1;
        int bucket_end = static_cast<int>((i + 2) * bucket_size) + 1;
        if (bucket_end >= data_count) bucket_end = data_count - 1;

        // 下一个桶的第一个点（作为"参考点"）
        QPointF next = data[bucket_end];

        // 🎯 计算当前桶内每个点与 (prev, next) 连线的三角形面积
        // 选面积最大的点——它离连线最远，最能体现曲线"拐弯"
        double max_area = -1.0;
        int max_index = bucket_start;

        for (int j = bucket_start; j < bucket_end; ++j) {
            double area = triangleArea(data[prev_index], data[j], next);
            if (area > max_area) {
                max_area = area;
                max_index = j;
            }
        }

        sampled.push_back(data[max_index]);
        prev_index = max_index;
    }

    sampled.push_back(data.last());   // 保留最后一个点
    return sampled;
}

/// @brief 计算三点形成的三角形面积（绝对值）
inline double triangleArea(const QPointF& a, const QPointF& b, const QPointF& c)
{
    // 叉积的一半 = 三角形面积
    // (x2-x1)(y3-y1) - (x3-x1)(y2-y1)
    double area = (b.x() - a.x()) * (c.y() - a.y())
                - (c.x() - a.x()) * (b.y() - a.y());
    return std::abs(area);
}
```

**在 HistoryTrend 中应用降采样：**

```cpp
// HistoryTrend::onQuery() 里，查询结果填充曲线之前：

    // 构建原始点
    QVector<QPointF> raw_points;
    raw_points.reserve(static_cast<int>(records.size()));
    for (const auto& rec : records) {
        raw_points.append(QPointF(
            static_cast<double>(rec.timestamp_ms), rec.value));
    }

    // 🎯 降采样到最多 1000 个点
    QVector<QPointF> points = lttbDownsample(raw_points, 1000);

```

**验证效果：** 降采样前 50000 个点画图可能卡 2 秒，降采样到 1000 点后几乎瞬时完成，而曲线形状在视觉上几乎没有差别（因为人眼在屏幕上分辨不出 1000 点和 50000 点的区别）。

### 3.3 优化 RTDB：减少不必要的拷贝

**问题：** `getTagValue` 返回 `TagDataPoint` 的拷贝，高频调用时浪费。

**优化点 1：`getAllLatestValues` 预分配 + 引用**

第三阶段的实现已经做了 `reserve`。再优化一下，避免 `emplace_back` 的多次构造：

```cpp
std::vector<TagDataPoint> RealTimeDB::getAllLatestValues() const
{
    std::lock_guard<std::mutex> lock(m_mutex);
    std::vector<TagDataPoint> result;
    result.reserve(m_current_values.size());   // 预分配，避免多次扩容
    for (const auto& [name, point] : m_current_values) {
        result.push_back(point);   // 拷贝是必要的（返回副本保证线程安全）
    }
    return result;
}
```

**关键理解：** 这个拷贝是**必要的**——如果在锁外返回引用，其他线程可能同时修改，导致数据竞争。性能和安全之间，安全优先。

**优化点 2：`updateTagValue` 用 `std::move`**

```cpp
void RealTimeDB::updateTagValue(const std::string& tag_name,
                                double raw_value, Quality quality)
{
    TagDataPoint point;
    // ... 填充 point ...

    {
        std::lock_guard<std::mutex> lock(m_mutex);
        // 🎯 用 move 而不是 copy，减少一次深拷贝
        // TagDataPoint 里有 3 个 std::string，move 只转移指针不复制内容
        m_current_values[tag_name] = std::move(point);
    }
    // ...
}
```

`TagDataPoint` 里有 3 个 `std::string` 成员，拷贝一次要复制 3 段字符串内存；`std::move` 只把字符串的指针转移过去，几乎零成本。

### 3.4 优化字符串拼接：QStringBuilder

**问题：** `QString` 的 `+` 操作符每次都会创建中间临时对象。连续拼接 10 个字符串会产生 9 个临时对象。

```cpp
// 低效：产生多个临时 QString
QString s = a + b + c + d + e;

// 高效：一次构建（需要 C++ 的 % 运算符重载，QStringBuilder 提供）
#include <QStringBuilder>
QString s = a % b % c % d % e;
```

**使用前提：** 需要 `QT_USE_QSTRINGBUILDER` 宏，或显式包含 `<QStringBuilder>` 并用 `%` 运算符。

在本项目的报表生成（大量字符串拼接）里，这个优化收益明显：

```cpp
// ReportGenerator::buildProductionTable() 里，原来用 + 拼接：
//   html += "<tr>" + name + "</tr>";
// 改成用 % 拼接（配合 QStringBuilder）
```

**RingBuffer 已经做了**（固定容量、无动态分配）。

**趋势曲线可复用 QVector：**


### 4.0 预备知识：代码审查看什么

#### A. 内存安全

## 第六章：发布打包

### 6.0 预备知识：Debug 和 Release 的区别

前四阶段我们一直用 Debug 构建（`cmake --preset=debug`）。Debug 和 Release 的核心区别：

| 特性 | Debug | Release |
|------|-------|---------|
| 调试符号 | 有（能断点、看变量） | 无（或单独 .pdb） |
| 优化级别 | 关闭（/Od） | 全优化（/O2） |
| 运行速度 | 慢 | 快（可能快 2-10 倍） |
| 文件体积 | 大 | 小 |
| 用途 | 开发调试 | 交付用户 |

**发布必须用 Release**，否则程序又慢又大，还暴露了调试信息。

### 6.1 编译 Release 版本

在 PowerShell 执行：

```powershell
cd D:\QtProject\UCS

# 用 release 预设编译
cmake --preset=release
cmake --build --preset=release
```

编译产物在 `build/release/src/app/Release/UCS.exe`。

### 6.2 用 windeployqt 收集依赖

`windeployqt` 在 Qt 安装目录的 bin 下，比如 `D:\Qt\6.5.3\msvc2019_64\bin\windeployqt.exe`。

**先创建一个干净的发布目录：**

```powershell
# 创建发布目录
New-Item -Path "D:\QtProject\UCS\release" -ItemType Directory -Force
# 拷贝 exe
Copy-Item "D:\QtProject\UCS\build\release\src\app\Release\UCS.exe" `
          "D:\QtProject\UCS\release\" -Force
```

**运行 windeployqt：**

```powershell
# 切换到发布目录
cd D:\QtProject\UCS\release

# 运行 windeployqt（注意路径按你的实际 Qt 安装位置）
& "D:\Qt\6.5.3\msvc2019_64\bin\windeployqt.exe" UCS.exe
```

windeployqt 会自动分析 UCS.exe 依赖哪些 Qt 模块，然后复制对应的 DLL：

```
release/
├── UCS.exe
├── Qt6Core.dll
├── Qt6Widgets.dll
├── Qt6Charts.dll
├── Qt6Sql.dll
├── Qt6SerialBus.dll
├── Qt6Network.dll
├── ...
├── platforms/
│   └── qwindows.dll          ← Windows 平台插件（必须）
├── styles/                   ← 样式插件
├── sqldrivers/
│   └── qsqlite.dll           ← SQLite 驱动
└── ...
```

**特别提醒几个容易漏的东西：**

1. **platforms/qwindows.dll**：没有它程序启动就闪退，且报错信息不明显
2. **sqldrivers/qsqlite.dll**：没有它历史数据库功能不可用
3. **资源文件**：如果日志目录、配置目录是运行时生成的，不用打包；但初始配置模板要放进去

### 6.3 写一键打包脚本

**文件路径：** `D:\QtProject\UCS\scripts\package_release.ps1`

```powershell
# ============================================================
# 发布打包脚本
#
# 做三件事：
#   1. 编译 Release 版本
#   2. 拷贝 exe 到发布目录
#   3. 运行 windeployqt 收集 Qt DLL
#
# 用法：.\scripts\package_release.ps1
# ============================================================

$ProjectRoot = Split-Path -Parent (Split-Path -Parent $PSScriptRoot)
$QtBin = "D:\Qt\6.5.3\msvc2019_64\bin"
$ReleaseDir = Join-Path $ProjectRoot "release"

Write-Host "[1/4] 编译 Release..." -ForegroundColor Cyan
Set-Location $ProjectRoot
cmake --preset=release
if ($LASTEXITCODE -ne 0) { exit 1 }
cmake --build --preset=release
if ($LASTEXITCODE -ne 0) { exit 1 }

Write-Host "[2/4] 创建发布目录..." -ForegroundColor Cyan
New-Item -Path $ReleaseDir -ItemType Directory -Force | Out-Null

Write-Host "[3/4] 拷贝可执行文件..." -ForegroundColor Cyan
Copy-Item (Join-Path $ProjectRoot "build/release/src/app/Release/UCS.exe") `
          $ReleaseDir -Force

Write-Host "[4/4] 收集 Qt 依赖..." -ForegroundColor Cyan
Set-Location $ReleaseDir
& (Join-Path $QtBin "windeployqt.exe") "UCS.exe"

Write-Host "打包完成！发布目录：$ReleaseDir" -ForegroundColor Green
```

### 6.4 验证发布包

验证发布包的正确方法：**在没有装 Qt 的电脑上运行**（或者临时把 Qt 从 PATH 里移除）。

```powershell
# 临时移除 Qt 环境变量，模拟"干净"环境
$oldPath = $env:Path
$env:Path = $env:Path -replace "D:\\Qt\\6.5.3\\msvc2019_64\\bin;", ""

# 运行程序
cd D:\QtProject\UCS\release
.\UCS.exe

# 恢复环境变量
$env:Path = $oldPath
```

如果程序能正常启动，说明依赖收集完整。如果报"缺少某 DLL"，说明 windeployqt 没收集到，需要手动补充。

### 6.5 压缩发布包

用压缩工具把 release 目录打包成 zip，方便传递。或者用 PowerShell：

```powershell
Compress-Archive -Path "D:\QtProject\UCS\release\*" `
                 -DestinationPath "D:\QtProject\UCS\UCS_v1.0_win64.zip"
```
