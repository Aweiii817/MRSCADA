## 开篇：预备知识——第二阶段涉及的几个核心概念

在开始之前，有几个工业自动化的基础知识需要搞明白。理解了这些，后面的代码才有意义。

### 1. 什么是"仿真"？为什么需要仿真引擎？

在真实的工厂中，上位机连接的是 PLC（可编程逻辑控制器）或者 DCS（分散控制系统）。PLC 连接着现场的传感器和执行器，上位机通过 Modbus 等协议从 PLC 读取数据。

但你在自己电脑上学习，没有真实的 PLC，也没有传感器给你采集数据。所以我们需要**用软件模拟一个"虚拟工厂"**——这就是仿真引擎（SimEngine）干的事。

仿真引擎的作用：

1. 模拟传感器数据的动态变化（温度慢慢升高、液位逐渐上升）
2. 响应上位机发出的控制命令（打开阀门 → 液位开始下降）
3. 模拟故障场景（传感器断线、超温报警）

UI 层完全不知道数据是来自仿真引擎还是真实 PLC——因为 Both 都通过 RealTimeDB 的中转。

### 2. 什么是 Modbus 协议？

Modbus 是工业自动化领域最常用的通信协议，1979 年由 Modicon 公司发明。为什么它流传了 40 多年还在用？因为**简单、开放、可靠**。

Modbus 有两种主要形式：

**Modbus RTU（串口模式）**

```
物理层：RS-232（点对点，15 米以内）或 RS-485（总线型，1200 米）
数据格式：地址(1字节) + 功能码(1字节) + 数据(N字节) + 校验(2字节)
通信方式：一问一答——主站发请求，从站回复
```

**Modbus TCP（网络模式）**

```
物理层：以太网（标准网线）
端口：502
数据格式：Modbus 协议包外面套一层 TCP 头
通信方式：也是问答，但不限制必须先问后答
```

**Modbus 的数据模型：**

```
┌──────────────────┐
│  线圈 (Coils)     │  DO — 数字量输出（可读可写），地址 00001-09999
├──────────────────┤
│  离散输入          │  DI — 数字量输入（只读），地址 10001-19999
├──────────────────┤
│  输入寄存器        │  AI — 模拟量输入（只读），地址 30001-39999
├──────────────────┤
│  保持寄存器        │  AO — 模拟量输出（可读可写），地址 40001-49999
└──────────────────┘
```

**功能码（最常用的几个）：**

```
01 (0x01) — 读线圈
02 (0x02) — 读离散输入
03 (0x03) — 读保持寄存器
04 (0x04) — 读输入寄存器
05 (0x05) — 写单个线圈
06 (0x06) — 写单个寄存器
15 (0x0F) — 写多个线圈
16 (0x10) — 写多个寄存器
```

在我们的项目中，4-20mA 模拟量传感器映射到**保持寄存器（功能码 03/06）**，阀门开关映射到**线圈（功能码 01/05）**。

### 3. 什么是 OPC UA？

OPC UA（Unified Architecture）是比 Modbus 更现代化的工业通信标准。它不是简单的"读寄存器"，而是：

- 面向对象的数据模型（节点 + 属性 + 方法）
- 内置安全机制（加密、认证）
- 支持历史数据访问
- 跨平台（Windows/Linux/嵌入式）

在工厂的层级中：

```
ERP 层（企业管理）—— 不直接连设备
    ↑
MES 层（生产执行）—— 连 OPC UA 服务器
    ↑
车间层（监控）—— OPC UA 服务器 + Modbus TCP
    ↑
现场层（设备）—— Modbus RTU（串口连接 PLC）
```

### 4. 什么是 MQTT？

MQTT 是一种"发布/订阅"模式的轻量级消息协议，常用于物联网（IoT）场景：

- **发布者（Publisher）**：把消息发到 Broker（消息代理）
- **订阅者（Subscriber）**：告诉 Broker"我想接收某某主题的消息"
- **Broker**：中转站，把消息从发布者转给订阅者

```
温度传感器（发布者）
    │ 发布"factory/reactor1/temp = 150.3"
    ▼
MQTT Broker（如 Mosquitto）
    │
    ├──→ 上位机（订阅"factory/reactor1/#"）
    │
    └──→ 手机 App（订阅"factory/reactor1/temp"）
```

MQTT 在工业中的典型用途：把车间数据上传到云端，让管理层在手机上就能看到生产状况。

### 5. 阶段目标与验收标准

第二阶段结束时，你应该能看到：

1. **仿真引擎在后台运行**：反应釜的温度、压力、液位像真实工厂一样自动变化
2. **数据在 UI 上更新**：程序启动后，你能看到数值在跳动（即使没有连接任何真实设备）
3. **Modbus RTU/TCP 通信框架**：能扫描虚拟串口上的 Modbus 设备，读取寄存器
4. **通信抽象层**：UI 不需要关心数据来自仿真引擎、Modbus 还是 OPC UA
5. **编码规范**：所有新增代码延续第一阶段的风格——异常处理、日志、注释齐全

### 6. 与第一阶段的关系

第一阶段建立的基础设施：

## 第一章：写仿真引擎——让数据自己动起来

### 1.0 预备知识

**为什么先写仿真引擎？**

在工业现场，数据流动是这样的：

```
传感器 → PLC → Modbus → 上位机 → RealTimeDB → UI
```

但在学习时，你没有传感器和 PLC。如果你先写 Modbus 代码，你会面临一个问题：**测试的时候连什么？**

解决方案就是先写仿真引擎。它扮演 PLC 的角色，产生看起来像是真实反应釜的数据——温度慢慢变化、液位随着阀门开度升降。这样：

1. 你可以在没有硬件的情况下测试整个数据链路
2. Modbus 代码写完后，可以把仿真引擎"切换"成 Modbus 驱动，UI 完全不需要改
3. 生产调试时，仿真引擎可以作为"备用数据源"——真实 PLC 离线时自动切到仿真模式

**什么是 FOPDT 模型？**

FOPDT = First Order Plus Dead Time（一阶加纯滞后）。这是过程控制中最基本的数学模型。

反应釜加热过程的真实写照：

1. 你**打开蒸汽阀**（输入变化）
2. 等了若干秒（纯滞后——蒸汽需要时间流过管道）
3. 温度开始**缓慢上升**（一阶惯性——热量传递需要时间）
4. 最终稳定在新的温度（达到稳态）

数学形式：

```
变化率 = K × (输入 - 当前值) / T   （当 当前值 < 目标值时）
```

- K = 增益（阀门全开能升多少度）
- T = 时间常数（惯性大小，T 越大响应越慢）

我们不需要你精通数学，只需要理解这个逻辑，然后翻译成代码。

### 1.3 理解反应釜的数学模型

在写代码之前，先想清楚我们要模拟什么。

回忆第一阶段规划中的反应釜：

```
原料 A ──→┐
           ├──→ 反应釜 ──→ 产物
原料 B ──→┘    │
               ├─ 夹套（加热/冷却）
               ├─ 搅拌电机
               └─ 安全阀
```

一个完整的反应过程分 5 个阶段：

| 阶段    | 发生了什么      | 哪些量在变化                  |
| ----- | ---------- | ----------------------- |
| 1. 进料 | 原料泵入反应釜    | 液位从 0% ↑ 到 80%          |
| 2. 加热 | 蒸汽加热夹套     | 温度从 25°C ↑ 到 150°C，压力 ↑ |
| 3. 恒温 | PID 调节维持恒温 | 温度稳定 150°C，压力稳定         |
| 4. 冷却 | 切换冷却水      | 温度从 150°C ↓ 到 50°C      |
| 5. 出料 | 打开出料阀      | 液位从 80% ↓ 到 5%          |

**数学模型（简化版）：**

我们要模拟的核心规律：

1. **温度变化**（加热时）：
   
   ```
   温度变化率 = 加热功率 × (目标温度 - 当前温度) / 时间常数
   ```
   
   开始时温差大，升温快；越接近目标温度，升温越慢（指数曲线）。

2. **液位变化**（进料/出料时）：
   
   ```
   液位变化率 = (流入速度 - 流出速度) / 釜截面积
   ```
   
   只要阀门开度固定，液位变化是线性的。

3. **压力变化**：
   
   ```
   压力 ≈ 基础压力 + 温度 × 系数
   ```
   
   温度升高，压力升高（近似线性关系）。

4. **传感器噪声**：
   真正的传感器读数会有微小波动（±0.5%）。我们在仿真值上加一点随机数，
   让它看起来更真实。

### 1.4 写 SimReactorModel（反应釜数学模型）

**文件路径：** `D:\QtProject\UCS\src\simulation\SimReactorModel.h`

这个类封装了反应釜的"物理规律"。它不关心谁调用了它、数据去了哪里，它只回答一个问题：**给定当前状态和阀门操作，下一时刻的状态是什么？**

```cpp
// ============================================================
// SimReactorModel.h — 反应釜数学模型
//
// 这个类模拟一个化工反应釜的动态行为。
// 它内部维护着温度、压力、液位等过程变量的当前值，
// 每次调用 step() 就往前推进一个时间步长。
//
// 这不是一个精确的物理仿真，而是一个"看起来像真的"
// 的简化模型，用于演示上位机的数据采集和监控功能。
// ============================================================
#pragma once

#include <string>
#include <random>   // 用于生成随机噪声

/// @brief 反应釜的过程变量快照
/// 每个字段对应一个 Tag 位号
struct ReactorState
{
    double temperature;     // TE-101：釜内温度 (°C)
    double jacket_temp;     // TE-102：夹套温度 (°C)
    double pressure;        // PT-101：釜内压力 (MPa)
    double level;           // LT-101：釜内液位 (%)
    double feed_a_flow;     // FT-101：进料A流量 (L/h)
    double feed_b_flow;     // FT-102：进料B流量 (L/h)
    double agitator_speed;  // TT-101：搅拌转速 (RPM)

    // 阀门状态（0.0 = 全关, 1.0 = 全开）
    double valve_hv101;     // HV-101：进料A阀
    double valve_hv102;     // HV-102：进料B阀
    double valve_hv103;     // HV-103：出料阀
    double valve_tv101;     // TV-101：蒸汽调节阀
    double valve_tv102;     // TV-102：冷却水调节阀
    double valve_pv101;     // PV-101：泄压阀

    /// @brief 重置到初始状态（冷启动）
    void reset()
    {
        temperature = 25.0;      // 室温
        jacket_temp = 25.0;
        pressure = 0.1;          // 常压
        level = 0.0;             // 空釜
        feed_a_flow = 0.0;
        feed_b_flow = 0.0;
        agitator_speed = 0.0;
        valve_hv101 = 0.0;       // 全关
        valve_hv102 = 0.0;
        valve_hv103 = 0.0;
        valve_tv101 = 0.0;
        valve_tv102 = 0.0;
        valve_pv101 = 0.0;
    }
};

/// @brief 工艺阶段枚举
/// 每个阶段对应反应过程中的一段连续的操作
enum class ProcessStage
{
    IDLE,           // 待机：什么都不做
    FEEDING,        // 进料：打开进料阀，液位上升
    HEATING,        // 加热：打开蒸汽阀，温度上升
    REACTING,       // 恒温反应：PID 调节维持恒温
    COOLING,        // 冷却：打开冷却水阀，温度下降
    DISCHARGING     // 出料：打开出料阀，液位下降
};

/// @brief 仿真参数
/// 控制反应釜的动态特性（"物理参数"）
struct ReactorParams
{
    double volume = 5.0;            // 反应釜容积 (m³)
    double max_temp = 300.0;        // 最高允许温度 (°C)
    double max_pressure = 2.5;      // 最高允许压力 (MPa)
    double heat_time_const = 120.0; // 加热时间常数（秒）——越大加热越慢
    double cool_time_const = 180.0; // 冷却时间常数（秒）
    double noise_level = 0.005;     // 传感器噪声幅度（±0.5%）

    // 手动操作设定值（由外部UI或配方设置）
    double setpoint_temp = 150.0;        // 目标温度 (°C)
    double setpoint_level = 80.0;        // 目标液位 (%)
    double feed_rate = 15.0;             // 进料速率 (% 液位/秒)
    double discharge_rate = 8.0;         // 出料速率 (% 液位/秒)

    // 阀门特性
    double valve_full_flow = 500.0;      // 阀门全开时的流量 (L/h)
};

/// @brief 反应釜模型类
///
/// 使用示例：
///   SimReactorModel reactor;
///   reactor.setParams(params);
///   reactor.setStage(ProcessStage::HEATING);
///
///   while (running) {
///       reactor.step(0.1);  // 推进 100ms
///       auto state = reactor.getState();
///       // 把 state 里的值推到 RealTimeDB...
///   }

{
public:
    SimReactorModel();
    ~SimReactorModel() = default;

    void setParams(const ReactorParams& params);
    const ReactorParams& params() const;

    /// @brief 获取当前状态

    /// @brief 切换工艺阶段

    /// @brief 获取当前工艺阶段
    ProcessStage currentStage() const;

    /// @brief 获取当前阶段的已运行时间（秒）
    double stageElapsedTime() const;

    /// @brief 设置某个阀门的开度（0.0 ~ 1.0）
    /// @param tag_name 位号，如 "HV-101"
    /// @param position 开度 0.0 ~ 1.0
    void setValve(const std::string& tag_name, double position);

    /// @param dt_seconds 时间步长，单位秒（通常 0.1 ~ 1.0 秒）
    ///
    /// 调用一次 step，内部按当前阀门状态和工艺阶段

{

    // 如果传入 -0.5，clamp 后变成 0.0
    // 如果传入 1.5，clamp 后变成 1.0

void SimReactorModel::step(double dt_seconds)
{
    // 保护：时间步长不能太大或太小
    if (dt_seconds <= 0.0 || dt_seconds > 10.0) return;

    m_stage_elapsed += dt_seconds;

    // 按顺序更新各个过程变量
    // 顺序有讲究：先更新流量（阀门驱动流量），
    // 再更新液位（流量决定液位），
    // 最后更新温度（加热/冷却影响温度）
    updateFlow(dt_seconds);
    updateLevel(dt_seconds);
    updateTemperature(dt_seconds);
    updatePressure(dt_seconds);
}

void SimReactorModel::updateTemperature(double dt)
{
    double target_temp = m_params.setpoint_temp;
    double tau = m_params.heat_time_const;  // 时间常数

    // 🎯 根据工艺阶段决定温度变化方向
    switch (m_stage) {
    case ProcessStage::HEATING:
        // 加热阶段：蒸汽阀开度越大，升温越快
        // 一阶响应：当前温度越接近目标，升温越慢
        // dT/dt = (T_target - T) × valve_openness / tau
        if (m_state.temperature < target_temp) {
            double rate = (target_temp - m_state.temperature)
                        * m_state.valve_tv101 / tau;
            m_state.temperature += rate * dt;
        }

        // 夹套温度比釜内温度略高（热传导需要温差）
        m_state.jacket_temp = m_state.temperature + 30.0
                            * m_state.valve_tv101;
        break;

    case ProcessStage::REACTING:
        // 恒温反应阶段：微调维持恒温
        // 简单的比例控制（P 控制）
        {
            double error = target_temp - m_state.temperature;
            double correction = error * 0.1 * dt;
            m_state.temperature += correction;
        }
        m_state.jacket_temp = m_state.temperature + 10.0;
        break;

    case ProcessStage::COOLING:
        // 冷却阶段：冷却水阀开度越大，降温越快
        {
            double cool_tau = m_params.cool_time_const;
            double ambient = 25.0;  // 冷却水温度
            double rate = (ambient - m_state.temperature)
                        * m_state.valve_tv102 / cool_tau;
            m_state.temperature += rate * dt;
        }
        m_state.jacket_temp = m_state.temperature - 20.0
                            * m_state.valve_tv102;
        break;

    default:
        // IDLE/FEEDING/DISCHARGING 阶段：自然散热
        {
            double ambient = 25.0;
            double rate = (ambient - m_state.temperature) / 600.0;  // 10分钟降温到室温
            m_state.temperature += rate * dt;
        }
        m_state.jacket_temp = m_state.temperature;
        break;
    }

    // 物理限制：温度不能低于室温，不能超过最高允许温度
    m_state.temperature = std::clamp(m_state.temperature, 25.0, m_params.max_temp);
    m_state.jacket_temp = std::clamp(m_state.jacket_temp, 20.0, m_params.max_temp + 50.0);
}

void SimReactorModel::updateLevel(double dt)
{
    switch (m_stage) {
    case ProcessStage::FEEDING:
        // 进料阶段：液位按进料速率上升
        // 进料阀开度越大，进料越快
        if (m_state.level < m_params.setpoint_level) {
            m_state.level += m_params.feed_rate
                           * m_state.valve_hv101 * dt;
        }
        break;

    case ProcessStage::DISCHARGING:
        // 出料阶段：液位按出料速率下降
        if (m_state.level > 0.0) {
            m_state.level -= m_params.discharge_rate
                           * m_state.valve_hv103 * dt;
        }
        break;

    default:
        // 其他阶段液位不变
        break;
    }

    // 物理限制
    m_state.level = std::clamp(m_state.level, 0.0, 100.0);
}

void SimReactorModel::updatePressure(double dt)
{
    // 🎯 压力简化模型：压力 = 基础压力 + 温度系数
    // 温度升高 → 液体汽化增多 → 压力升高
    // 泄压阀打开时压力快速下降
    double base_pressure = 0.1;  // 常压 0.1 MPa

    // 温度对压力的影响（近似线性）
    double temp_contribution = (m_state.temperature - 25.0)
                             * 0.008;  // 每升高1°C增加0.008MPa

    double target_pressure = base_pressure + temp_contribution;

    // 泄压阀效果
    if (m_state.valve_pv101 > 0.01) {
        // 泄压阀打开，压力快速下降
        target_pressure -= m_state.valve_pv101 * 2.0 * dt;
    }

    // 一阶惯性逼近目标压力
    m_state.pressure += (target_pressure - m_state.pressure) * dt / 5.0;

    // 物理限制
    m_state.pressure = std::clamp(m_state.pressure, 0.0, m_params.max_pressure);
}

void SimReactorModel::updateFlow(double dt)
{
    // 🎯 流量由阀门开度决定
    // 阀门特性曲线：全开时流量 = valve_full_flow
    // 实际流量 = 阀门开度 × 全开流量（简化模型）
    m_state.feed_a_flow = m_state.valve_hv101 * m_params.valve_full_flow;
    m_state.feed_b_flow = m_state.valve_hv102 * m_params.valve_full_flow * 0.6;

    // 搅拌转速由配方决定，恒温反应阶段开启
    if (m_stage == ProcessStage::REACTING) {
        m_state.agitator_speed = 300.0;  // 300 RPM
    } else if (m_stage == ProcessStage::HEATING ||
               m_stage == ProcessStage::COOLING) {
        m_state.agitator_speed = 100.0;
    } else {
        m_state.agitator_speed = 0.0;
    }
}

double SimReactorModel::applyNoise(double value) const
{
    // 🎯 给传感器读数加上随机噪声
    // 噪声幅度：±m_params.noise_level × 量程
    // 使用正态分布：大部分噪声在平均附近，少数偏离较远
    if (value == 0.0) return 0.0;  // 零值不添加噪声

    double noise = m_noise_dist(m_rng) * m_params.noise_level * value;
    return value + noise;
}

void SimReactorModel::reset()
{
    m_state.reset();
    m_stage = ProcessStage::IDLE;
    m_stage_elapsed = 0.0;
    LOG_INFO("SimReactor: reset to initial state");
}

```cpp
// ============================================================
// SimEngine.h — 仿真引擎
//
// 它做的事情很简单：每隔 100ms 调用一次模型 step()，
// 然后把结果推送到 RealTimeDB。UI 通过信号收到更新。
//
// SimEngine 和 SimReactorModel 的区别：
//   SimReactorModel 是"物理规律"——只知道怎么算
//   SimEngine 是"控制器"——决定什么时候算、算完数据去哪
// ============================================================
#pragma once

#include <QObject>
#include <QTimer>
#include "SimReactorModel.h"

class SimEngine : public QObject
{
    Q_OBJECT

public:
    /// @brief 构造仿真引擎
    /// @param parent Qt 父对象
    explicit SimEngine(QObject* parent = nullptr);
    ~SimEngine() override = default;

    /// @brief 启动仿真
    /// @param interval_ms 更新间隔（毫秒），默认 100ms
    void start(int interval_ms = 100);

    /// @brief 停止仿真
    void stop();

    /// @brief 是否正在运行
    bool isRunning() const;

    /// @brief 获取底层模型引用（用于设置阀门、切换阶段等）
    SimReactorModel& model();
    const SimReactorModel& model() const;

signals:
    /// @brief 仿真循环每步完成时发出的信号
    /// @param timestamp_ms 当前时间戳
    /// UI 层可以连接这个信号来做同步更新
    void simulationStep(qint64 timestamp_ms);

private slots:
    /// @brief 定时器触发的仿真步进
    void onTimerTick();

private:
    /// @brief 将反应釜的状态值发布到 RealTimeDB
    void publishState();

    /// @brief 根据当前阶段判断是否需要自动切换

    // 组件
    SimReactorModel m_model;   // 反应釜数学模型
    QTimer* m_timer;           // Qt 定时器，驱动仿真循环

    // 运行状态
    bool m_running = false;

```cpp
// ============================================================
// SimEngine.cpp — 仿真引擎实现
// ============================================================
#include "SimEngine.h"
#include "core/rtdb/RealTimeDB.h"
#include "common/Logger.h"
#include <QDateTime>

SimEngine::SimEngine(QObject* parent)
    : QObject(parent)
{
    m_timer = new QTimer(this);

    // 🔗 定时器超时 → 执行仿真步进
    connect(m_timer, &QTimer::timeout,
            this, &SimEngine::onTimerTick);
}

void SimEngine::start(int interval_ms)
{
    if (m_running) {
        LOG_WARN("SimEngine: already running");
        return;
    }

    m_running = true;
    m_dt_seconds = interval_ms / 1000.0;  // 毫秒转秒

    // 重置模型到初始状态，从进料阶段开始
    m_model.reset();
    m_model.setStage(ProcessStage::FEEDING);

    // 🎯 启动定时器，定时器在 Qt 事件循环中工作
    // 也就是说，onTimerTick 不会在一个独立线程中执行，
    // 而是在主线程的事件循环里被调用
    // 好处：不需要考虑线程安全问题（因为 RealTimeDB 在同一个线程）
    // 坏处：如果 step() 计算耗时太长，会阻塞 UI
    // 对于我们的简单模型，step() 耗时 < 1ms，完全没问题
    m_timer->start(interval_ms);

    LOG_INFO("SimEngine: started (interval={}ms)", interval_ms);
}

void SimEngine::stop()
{
    if (!m_running) return;

    m_timer->stop();
    m_running = false;

    LOG_INFO("SimEngine: stopped");
}

bool SimEngine::isRunning() const
{
    return m_running;
}

SimReactorModel& SimEngine::model()
{
    return m_model;
}

const SimReactorModel& SimEngine::model() const
{
    return m_model;
}

void SimEngine::onTimerTick()
{
    // ----- 第一步：推进模型 -----
    m_model.step(m_dt_seconds);

    // ----- 第二步：检查阶段切换 -----
    checkStageTransition();

    // ----- 第三步：把状态写入 RealTimeDB -----
    publishState();

    // ----- 第四步：发出步进信号 -----
    emit simulationStep(QDateTime::currentMSecsSinceEpoch());
}

void SimEngine::publishState()
{
    // 🎯 这里把模型内部的状态变量逐个"发布"到 RealTimeDB
    // 对 RealTimeDB 来说，这些数据和从 Modbus 读到的一模一样
    //
    // 注意：applyNoise() 让数据看起来更真实——就像真正
    // 的传感器读数一样带有微小波动

    auto& rtdb = RealTimeDB::instance();
    const auto& s = m_model.getState();

    // 模拟量（带噪声）
    rtdb.updateTagValue("TE-101", m_model.applyNoise(s.temperature));
    rtdb.updateTagValue("TE-102", m_model.applyNoise(s.jacket_temp));
    rtdb.updateTagValue("PT-101", m_model.applyNoise(s.pressure));
    rtdb.updateTagValue("LT-101", m_model.applyNoise(s.level));
    rtdb.updateTagValue("FT-101", m_model.applyNoise(s.feed_a_flow));
    rtdb.updateTagValue("FT-102", m_model.applyNoise(s.feed_b_flow));
    rtdb.updateTagValue("TT-101", m_model.applyNoise(s.agitator_speed));

    // 阀门状态作为数字量（0 或 1，不带噪声）
    double hv101_val = (s.valve_hv101 > 0.5) ? 1.0 : 0.0;
    double hv103_val = (s.valve_hv103 > 0.5) ? 1.0 : 0.0;

    rtdb.setTagValue("HV-101", hv101_val);
    rtdb.setTagValue("HV-102", (s.valve_hv102 > 0.5) ? 1.0 : 0.0);
    rtdb.setTagValue("HV-103", hv103_val);
    rtdb.setTagValue("PV-101", (s.valve_pv101 > 0.5) ? 1.0 : 0.0);
}

void SimEngine::checkStageTransition()
{
    // 🎯 自动阶段切换逻辑
    // 当某个工艺条件满足时，自动进入下一个阶段
    // 不需要外部干预——就像一个全自动反应釜

    double elapsed = m_model.stageElapsedTime();
    const auto& s = m_model.getState();

    switch (m_model.currentStage()) {
    case ProcessStage::FEEDING:
        // 液位达到目标值 → 切换加热
        if (s.level >= m_model.params().setpoint_level * 0.98) {
            // 关闭进料阀，打开蒸汽阀开始加热
            m_model.setValve("HV-101", 0.0);
            m_model.setValve("TV-101", 0.8);  // 蒸汽阀开 80%
            m_model.setStage(ProcessStage::HEATING);
            LOG_INFO("SimEngine: FEEDING → HEATING (level={:.1f})", s.level);
        }
        break;

    case ProcessStage::HEATING:
        // 温度达到目标 → 切换恒温反应
        if (s.temperature >= m_model.params().setpoint_temp * 0.97) {
            // 关小蒸汽阀，维持温度
            m_model.setValve("TV-101", 0.3);
            m_model.setStage(ProcessStage::REACTING);
            LOG_INFO("SimEngine: HEATING → REACTING (temp={:.1f})", s.temperature);
        }
        break;

    case ProcessStage::REACTING:
        // 反应 60 秒 → 切换冷却
        if (elapsed >= 60.0) {
            m_model.setValve("TV-101", 0.0);   // 关蒸汽
            m_model.setValve("TV-102", 0.7);   // 开冷却水
            m_model.setStage(ProcessStage::COOLING);
            LOG_INFO("SimEngine: REACTING → COOLING (elapsed={:.0f}s)", elapsed);
        }
        break;

    case ProcessStage::COOLING:
        // 温度降至 50°C → 切换出料
        if (s.temperature <= 50.0) {
            m_model.setValve("TV-102", 0.0);   // 关冷却水
            m_model.setValve("HV-103", 1.0);   // 开出料阀
            m_model.setStage(ProcessStage::DISCHARGING);
            LOG_INFO("SimEngine: COOLING → DISCHARGING (temp={:.1f})", s.temperature);
        }
        break;

    case ProcessStage::DISCHARGING:
        // 液位基本排空 → 回到待机
        if (s.level <= 5.0) {
            m_model.setValve("HV-103", 0.0);   // 关出料阀
            m_model.setStage(ProcessStage::IDLE);
            LOG_INFO("SimEngine: DISCHARGING → IDLE (batch complete)");
        }
        break;

    default:
        break;
    }
}

**什么是接口（Interface）？为什么需要抽象层？**

想象你有一个 USB 充电器。不管插的是 iPhone（Lightning 接口）、安卓手机（Type-C 接口）还是老款手机（Micro-USB），只要换个线，充电器本身不用换。

编程中的接口也是这个道理。不同的通信协议（Modbus、OPC UA、MQTT）就是不同的"线"，而上位机的业务逻辑（报警、数据记录、UI）就是"充电器"。如果把代码直接和 Modbus 绑定，换 OPC UA 时要改所有代码。有了抽象接口，切换协议只需要替换一个"插头"。
```

没有抽象层（紧耦合）：
  UI → 直接调用 Modbus 函数 → Modbus 设备
  UI → 直接调用 OPC UA 函数 → OPC UA 设备
  问题：换协议要改 UI 代码

有抽象层（松耦合）：
  UI → ICommunicationPort（抽象接口）
          ├── ModbusPort（具体实现）
          ├── OPCUAPort（具体实现）
          └── SimPort（仿真实现）
  好处：UI 只跟接口交互，换协议不需要改 UI

```
**C++ 中的纯虚函数：**

```cpp
class ICommunicationPort {
public:
    // = 0 表示"纯虚函数"——子类必须实现这个方法
    virtual bool connect() = 0;     // 连接设备
    virtual void disconnect() = 0;  // 断开连接
    virtual bool readTag(const std::string& tag, double& value) = 0;  // 读数据
};
```

- 有纯虚函数的类叫"抽象类"——不能直接创建它的对象
- 子类必须实现所有纯虚函数，否则子类也是抽象类
- 这保证了所有子类都有 `connect()`、`disconnect()`、`readTag()` 等相同的方法

**什么是策略模式？**

策略模式是一种设计模式：**定义一系列算法，把每个算法封装起来，让它们可以互相替换**。

在我们的场景中：

- "算法" = "数据采集方式"
- 策略 1 = 从仿真引擎读取数据
- 策略 2 = 从 Modbus 设备读取数据
- 策略 3 = 从 OPC UA 服务器读取数据

我们可以用一个统一的接口传递"采集策略"，代码不需要修改。

### 2.2 写 ICommunicationPort（抽象接口）

**文件路径：** `D:\QtProject\UCS\src\comm\ICommunicationPort.h`

这个头文件定义了所有通信协议都必须遵循的"约定"。不管是 Modbus、OPC UA 还是仿真引擎，都要实现这些方法。

```cpp
// ============================================================
// ICommunicationPort.h — 通信端口抽象接口
//
// 这是整个通信层的"宪法"——所有通信协议必须遵守这个接口。
// 不管底层是 Modbus、OPC UA、MQTT 还是仿真引擎，
// 上层代码都用同样的方式调用。
//
// 设计模式：策略模式（Strategy Pattern）
//   CommManager 持有 ICommunicationPort 指针，
//   具体指向 ModbusPort 还是 OPCUAPort 由配置决定。
// ============================================================
#pragma once

#include <string>
#include <vector>
#include <cstdint>

/// @brief 设备连接状态
enum class DeviceStatus : uint8_t
{
    DISCONNECTED = 0,   // 未连接
    CONNECTING   = 1,   // 正在连接
    CONNECTED    = 2,   // 已连接
    FAULT        = 3    // 故障（连接失败超过最大重试次数）
};

/// @brief 通信设备配置（基类）
/// 每个子类可以扩展自己的配置字段
struct DeviceConfig
{
    std::string device_name;       // 设备名称，如 "PLC-01"
    std::string protocol_type;     // 协议类型，如 "modbus_rtu"
    int poll_interval_ms = 500;    // 轮询间隔（毫秒）
    int timeout_ms = 1000;         // 超时时间（毫秒）
    int max_retries = 3;           // 最大重试次数
};

/// @brief 通信端口抽象基类
///
/// 🎯 为什么用抽象类而不是 C++ 的 interface 关键字？
/// C++ 没有 interface 关键字，用只包含纯虚函数的抽象类代替。
///
/// 为什么返回 bool 而不是抛出异常？
/// 工业通信中，超时、断线是"常态"而不是"异常"。
/// 用返回值表示成功/失败比异常更高效、更可预测。
class ICommunicationPort
{
public:
    virtual ~ICommunicationPort() = default;

    /// @brief 连接到设备
    /// @param config 设备配置（协议相关）
    /// @return true 连接成功，false 连接失败
    virtual bool connect(const DeviceConfig& config) = 0;

    /// @brief 断开连接
    virtual void disconnect() = 0;

    /// @brief 是否已连接
    /// @return true 已连接
    virtual bool isConnected() const = 0;

    /// @brief 获取设备状态
    virtual DeviceStatus status() const = 0;

    /// @brief 读取一个标签的值
    /// @param tag_name  位号，如 "TE-101"
    /// @param[out] value 输出参数，读取到的值
    /// @return true 读取成功
    virtual bool readTag(const std::string& tag_name, double& value) = 0;

    /// @brief 批量读取多个标签（性能优化）
    /// @param tag_names 位号列表
    /// @param[out] values 对应的值列表
    /// @return true 全部读取成功
    virtual bool readTags(const std::vector<std::string>& tag_names,
                          std::vector<double>& values) = 0;

    /// @brief 写入单个标签（写寄存器/线圈）
    /// @param tag_name  位号，如 "HV-101"
    /// @param value     要写入的值
    /// @return true 写入成功
    virtual bool writeTag(const std::string& tag_name, double value) = 0;

    /// @brief 获取协议名称
    /// @return 如 "Modbus RTU"
    virtual std::string protocolName() const = 0;

    /// @brief 执行一次轮询（批量读写所有配置的标签）
    /// @return true 轮询成功
    ///
    /// 🎯 这是最常用的方法：
    /// CommManager 的定时器每隔 poll_interval_ms 调用一次。
    /// 子类实现中，应该读取所有配置的标签，然后调用
    /// RealTimeDB::updateTagValue() 更新到实时数据库。
    virtual bool poll() = 0;
};
```

### 2.3 写 CommManager（通信管理器）

**文件路径：** `D:\QtProject\UCS\src\comm\CommManager.h`

CommManager 是通信层的"指挥官"。它管理多个 ICommunicationPort 实例（每台设备一个），统一调度轮询、重连、状态监控。

```cpp
// ============================================================
// CommManager.h — 通信管理器
//
// 它管理所有通信端口的生命周期：
//   1. 根据配置创建对应的 ICommunicationPort 实例
//   2. 定时轮询每个端口，将数据写入 RealTimeDB
//   3. 监控通信状态，异常时自动重连
//
// 可以管理多台设备：
//   "PLC-01" → ModbusRTU 端口（串口连接）
//   "PLC-02" → ModbusTCP 端口（以太网连接）
//   "OPC-GW" → OPC UA 端口
// ============================================================
#pragma once

#include <QObject>
#include <QTimer>
#include <memory>
#include <vector>
#include "ICommunicationPort.h"

class CommManager : public QObject
{
    Q_OBJECT

public:
    static CommManager& instance();

    /// @brief 初始化通信管理器（读取配置，创建设备端口）
    void initialize();

    /// @brief 启动所有设备的轮询
    void startAll();

    /// @brief 停止所有设备
    void stopAll();

    /// @brief 添加一个设备（从配置或 UI 操作）
    /// @return 设备名称（唯一标识）
    std::string addDevice(std::unique_ptr<ICommunicationPort> port,
                          const DeviceConfig& config);

    /// @brief 移除一个设备
    bool removeDevice(const std::string& device_name);

    /// @brief 根据名称查找端口
    ICommunicationPort* getPort(const std::string& device_name);

    /// @brief 获取所有设备状态
    std::vector<std::pair<std::string, DeviceStatus>> getAllStatus() const;

signals:
    /// @brief 设备连接状态变化
    void deviceStatusChanged(const QString& device_name, int status);

    /// @brief 设备轮询完成
    void devicePollCompleted(const QString& device_name, bool success);

private:
    CommManager();
    ~CommManager() override = default;

    struct DeviceEntry {
        std::string name;
        std::unique_ptr<ICommunicationPort> port;
        DeviceConfig config;
        int fail_count = 0;        // 连续失败次数（用于重连判断）
    };

    std::vector<DeviceEntry> m_devices;
    bool m_initialized = false;
};
```

**文件路径：** `D:\QtProject\UCS\src\comm\CommManager.cpp`

```cpp
// ============================================================
// CommManager.cpp — 通信管理器实现
// ============================================================
#include "CommManager.h"
#include "common/Logger.h"
#include "common/ConfigManager.h"
#include <QDateTime>
#include <algorithm>

CommManager& CommManager::instance()
{
    static CommManager inst;
    return inst;
}

CommManager::CommManager()
    : QObject(nullptr)
{
}

void CommManager::initialize()
{
    // 🎯 从 ConfigManager 读取通信设备配置
    // 第一阶段只有仿真引擎，第二阶段以后从这里读取真实的设备配置
    // 配置格式（在 config.json 中）：
    // {
    //   "comm": {
    //     "devices": [
    //       {"name":"PLC-01","protocol":"modbus_rtu","port":"COM1","baudrate":19200},
    //       {"name":"PLC-02","protocol":"modbus_tcp","host":"192.168.1.100","port":502}
    //     ]
    //   }
    // }

    auto& cfg = ConfigManager::instance();
    int device_count = cfg.getJsonValue<int>("comm.device_count", 0);

    if (device_count > 0) {
        // 有配置的设备，逐一创建端口
        for (int i = 0; i < device_count; ++i) {
            std::string prefix = "comm.devices[" + std::to_string(i) + "]";
            std::string name = cfg.getJsonValue<std::string>(prefix + ".name", "");
            std::string protocol = cfg.getJsonValue<std::string>(prefix + ".protocol", "");

            if (name.empty() || protocol.empty()) continue;

            LOG_INFO("CommManager: found device '{}' (protocol: {})", name, protocol);
            // 第二阶段只创建设备条目，端口实例化在第三阶段实现
        }
    }

    m_initialized = true;
    LOG_INFO("CommManager initialized with {} configured devices", device_count);
}

void CommManager::startAll()
{
    for (auto& entry : m_devices) {
        if (entry.port && !entry.port->isConnected()) {
            bool ok = entry.port->connect(entry.config);
            if (ok) {
                LOG_INFO("CommManager: device '{}' connected", entry.name);
            } else {
                LOG_WARN("CommManager: device '{}' connect failed", entry.name);
            }
        }
    }
    LOG_INFO("CommManager: started all devices");
}

void CommManager::stopAll()
{
    for (auto& entry : m_devices) {
        if (entry.port && entry.port->isConnected()) {
            entry.port->disconnect();
        }
    }
    LOG_INFO("CommManager: stopped all devices");
}

std::string CommManager::addDevice(
    std::unique_ptr<ICommunicationPort> port,
    const DeviceConfig& config)
{
    // 检查设备名是否重复
    for (const auto& entry : m_devices) {
        if (entry.name == config.device_name) {
            LOG_WARN("CommManager: device '{}' already exists", config.device_name);
            return "";
        }
    }

    DeviceEntry entry;
    entry.name = config.device_name;
    entry.port = std::move(port);
    entry.config = config;
    entry.fail_count = 0;

    m_devices.push_back(std::move(entry));
    LOG_INFO("CommManager: added device '{}' ({})",
             config.device_name, config.protocol_type);

    return config.device_name;
}

bool CommManager::removeDevice(const std::string& device_name)
{
    auto it = std::find_if(m_devices.begin(), m_devices.end(),
        [&](const DeviceEntry& e) { return e.name == device_name; });

    if (it != m_devices.end()) {
        if (it->port && it->port->isConnected()) {
            it->port->disconnect();
        }
        m_devices.erase(it);
        LOG_INFO("CommManager: removed device '{}'", device_name);
        return true;
    }
    return false;
}

ICommunicationPort* CommManager::getPort(const std::string& device_name)
{
    for (auto& entry : m_devices) {
        if (entry.name == device_name) {
            return entry.port.get();
        }
    }
    return nullptr;
}

std::vector<std::pair<std::string, DeviceStatus>> CommManager::getAllStatus() const
{
    std::vector<std::pair<std::string, DeviceStatus>> result;
    for (const auto& entry : m_devices) {
        DeviceStatus status = DeviceStatus::DISCONNECTED;
        if (entry.port) {
            status = entry.port->status();
        }
        result.emplace_back(entry.name, status);
    }
    return result;
}

## 第三章：实现 Modbus 通信

### 3.0 预备知识

**什么是 Modbus 寄存器？**

Modbus 设备内部有四种数据存储区：

```
┌─────────────────────────────────┐
│       Modbus 数据模型            │
├────────────┬────────────────────┤
│ 线圈 (Coil)  │ 数字量输出（可读可写） │
│ 00001-09999 │ 例：阀门开/关       │
├────────────┼────────────────────┤
│ 离散输入     │ 数字量输入（只读）    │
│ 10001-19999 │ 例：限位开关状态    │
├────────────┼────────────────────┤
│ 输入寄存器   │ 模拟量输入（只读）    │
│ 30001-39999 │ 例：4-20mA 原始值  │
├────────────┼────────────────────┤
│ 保持寄存器   │ 模拟量输出（可读可写） │
│ 40001-49999 │ 例：温度设定值      │
└────────────┴────────────────────┘
```

在我们的项目中：

- `TE-101`（温度）→ 保持寄存器 40001
- `HV-101`（阀门）→ 线圈 00001

**什么是 QtSerialBus？**

Qt 6 自带了 `QModbusClient` 类，它是 QtSerialBus 模块的一部分。这个类封装了 Modbus RTU 和 Modbus TCP 的底层细节，我们只需要配置参数然后调用读写方法。

使用 QtSerialBus 而不是自己从 socket 开始写 Modbus 协议的原因：

1. 不用自己拼 Modbus 帧（地址+功能码+数据+CRC）
2. 不用自己处理串口波特率、停止位等参数
3. 内置超时和重试机制
4. 信号槽异步通知读写结果（不会阻塞主线程）

**Modbus 的"一问一答"机制：**

```
主站（上位机）               从站（PLC）
    │                          │
    ├── 请求: 读寄存器 40001 ──→│
    │                          ├── 查找寄存器
    │  ←── 响应: 值 = 150.3 ───┤
    │                          │
    ├── 请求: 写线圈 00001=ON─→│
    │                          ├── 设置线圈
    │  ←── 响应: 写入成功 ────┤
    │                          │
```

注意：Modbus 是"半双工"的——同一时间只能有一方说话。上位机发出请求后必须等待回复，不能连续发两个请求。

### 3.1 理解 Modbus 地址和 Tag 的映射关系

我们的 Tag 定义（在 TagManager 中）有一个 `source_address` 字段，它存储了 Modbus 寄存器的地址。需要一个映射表把位号翻译成 Modbus 地址。

**文件路径：** `D:\QtProject\UCS\src\comm\modbus\ModbusMapping.h`

```cpp
// ============================================================
// ModbusMapping.h — Modbus 地址映射
//
// 把位号（如 "TE-101"）翻译成 Modbus 设备上的地址。
// 映射来自 TagManager 中每个 Tag 的 source_address 字段。
//
// Modbus 地址约定：
//   线圈（DO）：地址范围 00001-09999 → 内部地址 0-9998
//   保持寄存器（AO）：地址范围 40001-49999 → 内部地址 0-9998
// ============================================================
#pragma once

#include <string>
#include <unordered_map>
#include <vector>
#include <cstdint>

/// @brief Modbus 寄存器类型
enum class ModbusRegisterType : uint8_t
{
    COIL,           // 线圈（数字量输出，可读可写）
    DISCRETE_INPUT, // 离散输入（数字量输入，只读）
    HOLDING_REG,    // 保持寄存器（模拟量/数据，可读可写）
    INPUT_REG       // 输入寄存器（模拟量/数据，只读）
};

/// @brief 单个标签的 Modbus 映射
struct ModbusTagMapping
{
    std::string tag_name;           // 位号，如 "TE-101"
    int slave_address = 1;          // Modbus 从站地址（1-247）
    ModbusRegisterType reg_type;    // 寄存器类型
    int register_address = 0;       // 寄存器地址（从 0 开始）
    double scale = 1.0;             // 转换系数
    double offset = 0.0;            // 转换偏移
    // 工程值 = 原始值 × scale + offset
};

/// @brief Modbus 设备映射表
/// 一个 Modbus 设备可能包含多个标签
struct ModbusDeviceMapping
{
    std::string device_name;                // 设备名称
    std::vector<ModbusTagMapping> tags;     // 该设备的标签列表
};

/// @brief 映射管理器
/// 从 TagManager 中读取标签的 source_address 字段，
/// 生成 Modbus 地址映射。
class ModbusMappingManager
{
public:
    /// @brief 从 TagManager 构建映射表
    void buildFromTagManager();

    /// @brief 根据位号查找映射
    /// @return 找到返回 true
    bool findMapping(const std::string& tag_name,
                     ModbusTagMapping& out_mapping) const;

    /// @brief 根据设备名称获取该设备的所有映射
    const std::vector<ModbusTagMapping>* getDeviceMappings(
        const std::string& device_name) const;

private:
    // 按设备分组的映射表
    std::unordered_map<std::string, std::vector<ModbusTagMapping>> m_device_mappings;

    // 按位号索引的映射表（快速查找）
    std::unordered_map<std::string, ModbusTagMapping> m_tag_mappings;
};

```cpp
// ============================================================
// ModbusMapping.cpp — 映射管理实现
// ============================================================
#include "ModbusMapping.h"
#include "core/tag/TagManager.h"
#include "common/Logger.h"

void ModbusMappingManager::buildFromTagManager()
{
    m_device_mappings.clear();
    m_tag_mappings.clear();

    const auto& all_tags = TagManager::instance().allTags();

    for (const auto& tag_ptr : all_tags) {
        if (!tag_ptr) continue;

        ModbusTagMapping mapping;
        mapping.tag_name = tag_ptr->tag_name;
        mapping.slave_address = 1;  // 默认从站地址 1

        // 🎯 根据 Tag 的数据类型推断 Modbus 寄存器类型
        // FLOAT/DOUBLE → 保持寄存器（可读可写）
        // BOOL → 线圈（可读可写）
        switch (tag_ptr->data_type) {
        case DataType::BOOL:
            mapping.reg_type = ModbusRegisterType::COIL;
            break;
        default:
            mapping.reg_type = ModbusRegisterType::HOLDING_REG;
            break;
        }

        // source_address 0-9998 对应 Modbus 地址 40001-49999
        mapping.register_address = tag_ptr->source_address;
        mapping.scale = 1.0;
        mapping.offset = 0.0;

        // 按设备分组
        std::string device = tag_ptr->source_device.empty()
                             ? "default" : tag_ptr->source_device;

        m_device_mappings[device].push_back(mapping);
        m_tag_mappings[tag_ptr->tag_name] = mapping;
    }

    LOG_INFO("ModbusMapping: built {} mappings across {} devices",
             m_tag_mappings.size(), m_device_mappings.size());
}

bool ModbusMappingManager::findMapping(const std::string& tag_name,
                                       ModbusTagMapping& out_mapping) const
{
    auto it = m_tag_mappings.find(tag_name);
    if (it != m_tag_mappings.end()) {
        out_mapping = it->second;
        return true;
    }
    return false;
}

const std::vector<ModbusTagMapping>* ModbusMappingManager::getDeviceMappings(
    const std::string& device_name) const
{
    auto it = m_device_mappings.find(device_name);
    if (it != m_device_mappings.end()) {
        return &it->second;
    }
    return nullptr;
}

void ModbusRtuPort::configureSerialPort(const ModbusRtuConfig& cfg)
{
    // 🎯 把我们的配置参数翻译成 QtModbus 的串口设置
    // 这些参数必须和设备（PLC）的设置一致，否则通信失败

    // 设置串口号
    m_modbus->setConnectionParameter(
        QModbusDevice::SerialPortNameParameter,
        QString::fromStdString(cfg.port_name));

    // 设置波特率
    m_modbus->setConnectionParameter(
        QModbusDevice::SerialBaudRateParameter,
        cfg.baudrate);

    // 设置数据位（Modbus RTU 通常用 8 位）
    m_modbus->setConnectionParameter(
        QModbusDevice::SerialDataBitsParameter,
        cfg.data_bits);

    // 设置校验位
    // Qt 使用枚举值：NoParity=0, EvenParity=1, OddParity=2
    int parity = 0;
    switch (cfg.parity) {
    case 'E': case 'e': parity = 1; break;
    case 'O': case 'o': parity = 2; break;
    default: parity = 0; break;
    }
    m_modbus->setConnectionParameter(
        QModbusDevice::SerialParityParameter, parity);

    // 设置停止位
    m_modbus->setConnectionParameter(
        QModbusDevice::SerialStopBitsParameter,
        cfg.stop_bits);

    // 设置响应超时（等待设备回复的最大时间）
    m_modbus->setTimeout(cfg.timeout_ms);

    // 设置重试次数
    m_modbus->setNumberOfRetries(cfg.max_retries - 1);
}

bool ModbusRtuPort::connect(const DeviceConfig& config)
{
    // 如果已经连接，先断开
    if (m_modbus && m_modbus->state() == QModbusDevice::ConnectedState) {
        disconnect();
    }

    // 将通用配置转换为 Modbus RTU 专用配置
    const auto* rtu_config = dynamic_cast<const ModbusRtuConfig*>(&config);
    if (rtu_config) {
        m_config = *rtu_config;
    } else {
        // 如果传进来的不是 ModbusRtuConfig，用默认值
        LOG_WARN("ModbusRtuPort: using default config");
    }

    // 创建 Modbus RTU 主站对象
    m_modbus = std::make_unique<QModbusRtuSerialMaster>();

    // 配置串口参数
    configureSerialPort(m_config);

    // 🎯 连接到串口设备
    // 注意：QModbusRtuSerialMaster::connectDevice() 只是打开串口
    // 真正的 Modbus 通信在后续的读写操作中进行
    if (m_modbus->connectDevice()) {
        m_status = DeviceStatus::CONNECTED;
        LOG_INFO("ModbusRTU: connected to {} ({} baud, {}N1)",
                 m_config.port_name, m_config.baudrate);
        return true;
    } else {
        m_status = DeviceStatus::FAULT;
        LOG_ERROR("ModbusRTU: failed to connect to {} - {}",
                  m_config.port_name,
                  m_modbus->errorString().toStdString());
        return false;
    }
}

        m_modbus->disconnectDevice();
        m_modbus.reset();  // 释放 QModbusRtuSerialMaster 对象
    }
    m_status = DeviceStatus::DISCONNECTED;
    LOG_INFO("ModbusRTU: disconnected");

Modbus TCP 和 Modbus RTU 的区别：

- RTU 走串口（RS-232/485），TCP 走以太网

**数据链路回顾：**

**什么是 QTimer？**

`QTimer` 是 Qt 的定时器类。设置一个时间间隔后，它会定时发出 `timeout()` 信号。我们把更新界面的代码连接到这个信号上，界面就会定时刷新。

```
QTimer(1000ms)
    │ timeout()
    ▼
onTimerTick()
    ├── 从 RealTimeDB 读取最新数据
    └── 更新界面上的数字显示
```

**什么是 QLabel 动态更新？**

`QLabel` 可以显示文本，调用 `setText()` 方法就能改变显示内容。在 QTimer 的 timeout 信号槽里不断调用 setText，数字就会"跳动"起来。

void DashboardWidget::addParamRow(QGridLayout* grid, int row,
                                   const QString& tag_name,
                                   const QString& description,
                                   const QString& unit,
                                   const QString& color)
{
    // 🎯 每个参数用三个 QLabel 排列在一行里：

            .arg(tag_name, description));
    label_name->setStyleSheet(
        QString("background-color: %1; color: white; padding: 10px; "
                "border-radius: 6px; font-size: 14px; min-width: 140px;")
            .arg(color));
    label_name->setAlignment(Qt::AlignCenter);

    // 数值（大字显示）
    auto* label_value = new QLabel("---");
    label_value->setStyleSheet(
        "background-color: #2C3E50; color: #ECF0F1; "

        "font-size: 28px; font-weight: bold; min-width: 100px;");
    label_value->setAlignment(Qt::AlignCenter);

    // 单位
    auto* label_unit = new QLabel(unit);
    label_unit->setStyleSheet(
        "background-color: #34495E; color: #BDC3C7; "
        "padding: 10px; border-radius: 6px; font-size: 14px; min-width: 50px;");
    label_unit->setAlignment(Qt::AlignCenter);

    // 添加到网格（列占用 1:2:1 比例）
    grid->addWidget(label_name, row, 0);
    grid->addWidget(label_value, row, 1);
    grid->addWidget(label_unit, row, 2);

    // 保存卡片引用
    ParamCard card;

void DashboardWidget::refreshDisplay()
{
    // 🎯 定时刷新：遍历所有参数卡片，从 RealTimeDB 读取最新值并更新显示

    auto& rtdb = RealTimeDB::instance();

    for (auto& [tag_name, card] : m_cards) {
        TagDataPoint point;
        if (rtdb.getTagValue(tag_name, point)) {
            // 有数据：显示数值
            if (point.quality >= Quality::UNCERTAIN) {
                // 数据可用——正常显示数字
                QString value_text;
                if (point.data_type == DataType::BOOL) {
                    // 布尔量显示 "ON" / "OFF"
                    value_text = (point.scaled_value > 0.5) ? "ON" : "OFF";
                } else {
                    // 模拟量显示小数
                    value_text = QString::number(point.scaled_value, 'f', 1);
                }
                card.label_value->setText(value_text);

                // 数据正常 → 绿色文字
                card.label_value->setStyleSheet(
                    "background-color: #2C3E50; color: #2ECC71; "
                    "padding: 10px; border-radius: 6px; "
                    "font-size: 28px; font-weight: bold; min-width: 100px;");
            } else {
                // 数据不可用（BAD）→ 显示三条横线
                card.label_value->setText("---");
                card.label_value->setStyleSheet(
                    "background-color: #2C3E50; color: #E74C3C; "
                    "padding: 10px; border-radius: 6px; "
                    "font-size: 28px; font-weight: bold; min-width: 100px;");
            }
        }
        // 没有数据：保持 "---"
    }
}

## 第五章：OPC UA 与 MQTT 简介

（本章仅做概念介绍，完整实现在第三、四阶段）

### 5.1 OPC UA 能做什么

OPC UA 让你可以像访问文件系统一样访问设备的"信息模型"：

```
root/
├── Objects/
│   ├── Reactor1/
│   │   ├── Temperature  [150.3°C]  ← 可读写
│   │   ├── Pressure     [0.85 MPa]
│   │   ├── Valve_HV101  [ON]
│   │   └── StartBatch()            ← 可调用方法
│   └── Reactor2/
│       └── ...
└── Types/
    └── ...
```

与 Modbus 的对比：

| 特性   | Modbus   | OPC UA    |
| ---- | -------- | --------- |
| 数据模型 | 扁平（寄存器号） | 层级（对象+属性） |
| 安全   | 无        | 加密+认证     |
| 传输   | 串口/以太网   | 以太网       |
| 适用场景 | 现场设备层    | 车间到企业层    |
| 复杂度  | 低        | 高         |

### 5.2 MQTT 能做什么

MQTT 用于"数据上云"。典型的工厂架构：

```
车间层（上位机）── MQTT ──→ 云端服务器
                                 │
                            ┌────┴────┐
                            │         │
                            MES系统   手机 App
```

我们的 UCS 后续可以用 MQTT 把反应釜数据上传到本地 MQTT Broker（如 Mosquitto），其他系统可以订阅这些数据。

### 6.1 在状态栏显示通信状态

```cpp
// 在 MainWindow 构造函数中，添加通信状态刷新定时器
auto* comm_timer = new QTimer(this);
connect(comm_timer, &QTimer::timeout, this, [this]() {
    auto all_status = CommManager::instance().getAllStatus();
    if (all_status.empty()) {
        m_status_comm->setText("通信: 仿真模式");
        m_status_comm->setStyleSheet("color: #F39C12;");
    } else {
        bool all_ok = true;
        QString status_text;
        for (const auto& [name, status] : all_status) {
            if (!status_text.isEmpty()) status_text += " | ";
            switch (status) {
            case DeviceStatus::CONNECTED:
                status_text += QString::fromStdString(name) + ": 在线";
                break;
            case DeviceStatus::DISCONNECTED:
                status_text += QString::fromStdString(name) + ": 离线";
                all_ok = false;
                break;
            case DeviceStatus::FAULT:
                status_text += QString::fromStdString(name) + ": 故障";
                all_ok = false;
                break;
            default:
                status_text += QString::fromStdString(name) + ": ?";
                all_ok = false;
            }
        }
        m_status_comm->setText(status_text);
        m_status_comm->setStyleSheet(
            all_ok ? "color: #2ECC71;" : "color: #E74C3C;");
    }
});
comm_timer->start(2000);  // 每 2 秒检查一次
```
