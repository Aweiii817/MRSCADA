## 1. 项目概述

### 1.1 项目名称

**UCS — 工业上位机监控系统**（Upper Computer System for Chemical Process Control）

### 1.2 项目定位

面向精细化工行业的间歇式反应釜过程控制上位机系统，模拟从 DCS/PLC 层采集数据到上位机实时监控、历史追溯、报警管理、配方下发等完整的数据链路。项目聚焦 **C++/Qt 工程实践** 和 **工业通信协议** 两大企业核心技能栈。

### 1.3 项目目标

| 目标       | 说明                                              |
| -------- | ----------------------------------------------- |
| **技能覆盖** | 涵盖企业级上位机开发所需的 C++、Qt、多线程、网络编程、数据库、设计模式          |
| **协议贯通** | 串口（Modbus RTU）+ 网络（Modbus TCP、OPC UA、MQTT）全链路实现 |
| **工程规范** | CMake 构建、单元测试、日志、配置管理、插件架构                      |
| **领域仿真** | 模拟化工反应釜生产工艺，使项目有真实的业务背景                         |
| **交付质量** | 可演示、可迭代、可作为简历作品                                 |

## 2. 行业背景与工艺场景

### 2.1 为什么选择精细化工

精细化工（间歇式生产）是工业上位机的典型应用领域：

- 生产过程涉及 **温度、压力、液位、流量、pH** 等多种模拟量
- 包含 **PID 调节、联锁保护、配方切换** 等典型控制逻辑
- 对 **报警管理、历史追溯、权限管控** 有强需求
- 设备层常用 **Modbus RTU/TCP**，车间层用 **OPC UA**，云端用 **MQTT** — 协议栈完整

### 2.2 模拟工艺场景 — 聚合反应釜

选择 **聚合反应釜（Batch Reactor）** 作为核心工艺设备：

```
原料罐 A ──→┐
              ├──→ 反应釜 (Reactor) ──→ 产物储罐
原料罐 B ──→┘       │
                    ├─ 夹套冷却水（控温）
                    ├─ 搅拌电机
                    └─ 安全泄压阀
```

**工艺阶段：**

1. **进料** — 按配方比例将原料 A、B 泵入反应釜，监控液位
2. **加热升温** — 夹套蒸汽加热，以设定升温速率达到目标温度
3. **恒温反应** — PID 调节维持恒温，持续搅拌，监控压力
4. **冷却降温** — 切换冷却水，降温至出料温度
5. **出料** — 打开出料阀，排空反应釜

### 2.3 模拟测点清单

| 位号     | 描述      | 信号类型       | 数据范围         |
| ------ | ------- | ---------- | ------------ |
| TE-101 | 釜内温度    | AI（4-20mA） | 0 ~ 300 °C   |
| TE-102 | 夹套温度    | AI（4-20mA） | 0 ~ 200 °C   |
| PT-101 | 釜内压力    | AI（4-20mA） | 0 ~ 2.5 MPa  |
| LT-101 | 釜内液位    | AI（4-20mA） | 0 ~ 100 %    |
| FT-101 | 进料 A 流量 | AI（4-20mA） | 0 ~ 500 L/h  |
| FT-102 | 进料 B 流量 | AI（4-20mA） | 0 ~ 300 L/h  |
| TT-101 | 搅拌转速    | AI（脉冲）     | 0 ~ 1500 RPM |
| HV-101 | 进料 A 阀  | DO（ON/OFF） | 开/关          |
| HV-102 | 进料 B 阀  | DO（ON/OFF） | 开/关          |
| HV-103 | 出料阀     | DO（ON/OFF） | 开/关          |
| TV-101 | 蒸汽调节阀   | AO（4-20mA） | 0 ~ 100 %    |
| TV-102 | 冷却水调节阀  | AO（4-20mA） | 0 ~ 100 %    |
| PV-101 | 泄压阀     | DO（ON/OFF） | 开/关          |
| SC-101 | 搅拌电机变频器 | AO（4-20mA） | 0 ~ 50 Hz    |

**说明：** AI = 模拟量输入，AO = 模拟量输出，DI = 数字量输入，DO = 数字量输出

## 3. 系统总体架构

### 3.1 分层架构

```
┌────────────────────────────────────────────────────────────┐
│                    表示层（Presentation）                     │
│  Qt Widgets / QML   实时监控   趋势图   报警列表   报表     │
├────────────────────────────────────────────────────────────┤
│                    业务逻辑层（Business）                    │
│  报警引擎  配方管理  历史数据服务  操作权限  生产调度       │
├────────────────────────────────────────────────────────────┤
│                    数据管理层（Data）                        │
│  实时数据库（RTDB）  历史数据库（SQLite）  标签管理         │
├────────────────────────────────────────────────────────────┤
│                    通信抽象层（Communication）               │
│  协议管理器 | 插件加载器 | 数据帧解析 | 心跳监控           │
├──────────┬──────────┬──────────┬──────────┬────────────────┤
│ Modbus   │ Modbus   │  OPC UA  │  MQTT    │  仿真引擎      │
│ RTU      │ TCP      │  Client  │  Client  │  （模拟PLC）   │
├──────────┴──────────┴──────────┴──────────┴────────────────┤
│                   操作系统 / 硬件层                          │
│  Windows / 串口 / 以太网 / 文件系统                         │
└────────────────────────────────────────────────────────────┘
```

### 3.2 核心设计模式

| 模式                     | 应用位置        | 说明                   |
| ---------------------- | ----------- | -------------------- |
| **单例（Singleton）**      | 实时数据库、日志管理器 | 全局唯一访问点              |
| **观察者（Observer）**      | 数据点值变更通知    | Signal/Slot 机制天然实现   |
| **策略（Strategy）**       | 协议管理器       | 可动态切换通信协议实现          |
| **工厂（Factory）**        | 协议插件创建      | 根据配置创建设备通信实例         |
| **命令（Command）**        | 操作历史/撤销     | 操作指令的封装与日志           |
| **状态机（State Machine）** | 反应釜工艺流程     | Qt StateMachine 框架实现 |
| **组件（Component）**      | UI 面板组合     | 可复用的监控仪表盘组件          |
| **插件（Plugin）**         | 协议加载        | 动态加载 .dll 协议驱动       |

### 5.2 用户管理模块

**功能说明：** 用户登录、权限分级、操作审计。

- **用户角色：**
  - **操作员（Operator）**：查看实时数据、确认报警、切换画面
  - **工程师（Engineer）**：+ 修改参数、配置通信、修改配方
  - **管理员（Admin）**：+ 用户管理、系统配置、权限分配
- **技术实现：**
  - 登录界面：`QDialog` 封装
  - 权限管理：RBAC（基于角色的访问控制）模型
  - 密码存储：SHA-256 哈希 + Salt
  - 会话管理：`LoginSession` 单例，记录当前用户和权限级别
- **数据库表：** `users`、`roles`、`permissions`、`operation_log`

### 5.3 系统配置模块

**功能说明：** 系统运行参数配置管理。

- **配置分类：**
  - 通信配置（设备列表、协议类型、连接参数）
  - 采集配置（采集周期、数据点映射）
  - 报警配置（报警限值、优先级、通知方式）
  - 存储配置（历史数据保存周期、数据库路径）
  - 界面配置（语言、主题、布局）
- **技术实现：**
  - 配置存储：JSON 文件 + SQLite（运行时持久化）
  - 使用 `QSettings` 管理通用应用设置
  - 配置变更监听：Signal/Slot 通知各模块重新加载

### 5.4 实时监控模块

**功能说明：** 以多种可视化方式展示设备实时数据。

- **视图组件：**
  - **仪表盘概览（Dashboard）**：关键参数卡片、状态指示灯
  - **数据表格视图**：按设备/位号列示实时数值、单位、质量戳
  - **仪表盘仪表**：自绘仪表盘控件显示模拟量（温度表、压力表）
  - **状态位指示灯**：数字量状态（运行/停止、开/关）
- **技术实现：**
  - 数据刷新：`QTimer` 定时刷新（100ms ~ 1000ms 可配置）
  - 数据绑定：每个 `Tag`（数据点）持有当前值，UI 通过 Signal/Slot 订阅
  - 颜色编码：正常（绿）、警告（黄）、报警（红）、断开（灰）

### 5.5 工艺流程图模块

**功能说明：** 以 P&ID 风格展示反应釜工艺流程。

- **流程动画：**
  - 管道流动动画（流动的粒子或线段）
  - 泵/电机旋转动画
  - 液位动态填充（反应釜内液位随 LT-101 变化）
  - 阀门状态变色（开=绿，关=红）
  - 温度/压力数值在设备旁显示
- **推荐技术方案：** **QGraphicsView 框架 + 自定义 QGraphicsItem**
  - 平衡灵活性和性能
  - QGraphicsItem 子类化：`ReactorItem`、`PipeItem`、`ValveItem`、`PumpItem`
- **交互功能：**
  - 鼠标悬浮显示详细信息
  - 双击设备跳转到该设备详细面板
  - 缩放/平移导航
  - 工艺阶段高亮显示

### 5.6 趋势分析模块

**功能说明：** 实时趋势和历史趋势两种模式。

- **实时趋势（Real-time Trend）：**
  - X 轴：时间（滚动窗口，如最近 5 分钟、30 分钟）
  - Y 轴：量程自适应
  - 支持多曲线叠加对比
  - 十字光标跟踪查看数值
- **历史趋势（Historical Trend）：**
  - 时间范围选择器：日历/时间区间
  - 缩放、拖拽、游标测量
  - 查询条件：按位号、时间段、统计类型（平均值/最大值/最小值）
- **技术实现：**
  - 使用 **QtCharts** 的 `QLineSeries`、`QDateTimeAxis`、`QValueAxis`
  - 实时数据使用环形缓冲区（`QVector` + 滚动索引）避免频繁内存分配
  - 历史查询使用 SQL 的 WHERE 时间范围 + 降采样策略

### 5.7 报警管理模块

**功能说明：** 工业生产的核心安全功能。

- **报警类型：**
  - **高限报警（HH/H）**：高高限、高限
  - **低限报警（LL/L）**：低低限、低限
  - **变化率报警（ROC）**：单位时间内数值变化过快
  - **偏差报警（Dev）**：与设定值偏差过大
  - **数字量报警**：状态变位（如急停按下）
  - **通信故障报警**：设备离线
- **报警状态机：**

```
正常 ──→ 报警产生 ──→ 报警确认 ──→ 报警恢复 ──→ 恢复确认 ──→ 正常
```

- **功能列表：**
  - 报警实时列表（顶部固定、滚动、颜色闪烁）
  - 报警确认操作（单人确认、双人确认配置）
  - 报警历史查询（按时间、位号、类型过滤）
  - 报警声音提示（`QSoundEffect` 播放 WAV）
- **技术实现：**
  - 报警规则：可配置 JSON 规则文件
  - 报警评估：独立线程轮询所有标签
  - 报警优先级：CRITICAL > HIGH > MEDIUM > LOW

### 5.8 历史数据模块

**功能说明：** 历史数据存储、查询、导出。

- **存储策略：**
  - 实时数据压缩存储（死区压缩：变化超过阈值才存盘）
  - 自动化数据管理（定期归档、自动清理超过保存期的数据）
  - 快照存储（每分钟/每小时存一次瞬时值快照）
- **查询功能：**
  - 按时间范围 + 测点筛选
  - 统计查询（平均值、最大值、最小值、累计值）
  - 数据导出：CSV 格式
- **数据库表设计：**

```sql
-- 标签定义表
CREATE TABLE tags (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  tag_name TEXT UNIQUE NOT NULL,    -- 位号
  description TEXT,                  -- 描述
  unit TEXT,                         -- 单位
  data_type INTEGER,                -- 0:BOOL 1:INT16 2:FLOAT 3:DOUBLE
  scale REAL DEFAULT 1.0,           -- 转换系数
  offset REAL DEFAULT 0.0           -- 转换偏移
);

-- 历史数据表（按月分区，如 data_202607）
CREATE TABLE data_202607 (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  tag_id INTEGER NOT NULL,
  timestamp DATETIME NOT NULL,
  value REAL NOT NULL,
  quality INTEGER DEFAULT 192,      -- 0:Bad 64:Uncertain 192:Good
  FOREIGN KEY (tag_id) REFERENCES tags(id)
);

-- 索引
CREATE INDEX idx_data_time ON data_202607(tag_id, timestamp);
```

### 5.10 报表系统模块

**功能说明：** 自动生成生产报表、日报/月报。

- **报表类型：**
  - **班报（Shift Report）**：当前班次的生产数据汇总
  - **日报（Daily Report）**：24小时数据统计
  - **报警统计报表**：按时间段统计报警次数、类型分布
  - **产量报表**：批次产量统计
- **技术实现：**
  - 推荐方案：Qt 输出 HTML 表格 → 通过 `QTextDocument` 打印/导出 PDF

### 5.11 系统日志模块

**功能说明：** 记录系统运行日志和操作审计日志。

- **日志分类：**
  - **调试日志（Debug）**：开发者调试用
  - **信息日志（Info）**：正常操作记录
  - **警告日志（Warning）**：非正常但可恢复的状态
  - **错误日志（Error）**：系统错误、通信失败
- **日志输出目标：**
  - 控制台（开发调试）
  - 文件（按天/大小滚动，保留 30 天）
  - 数据库（操作审计日志）
- **技术实现：**
  - 使用 **spdlog** 管理日志输出
  - 自定义 Qt Message Handler：`qInstallMessageHandler` 将 `qDebug`/`qWarning`/`qCritical` 重定向到 spdlog

### 5.12 仿真引擎模块

**功能说明：** 在没有真实 PLC 的情况下模拟生产过程。

- **仿真模型：**
  - 一阶惯性 + 纯滞后 (FOPDT) 模型模拟温度变化
  - 积分模型模拟液位变化
  - 压力与温度耦合模型（温度升高 → 压力升高）
  - 阀门特性曲线（阀门开度 → 流量关系）
  - 随机噪声叠加（模拟传感器噪声）
- **仿真模式：**
  - **手动模式**：手动调节阀门开度，观察响应
  - **自动模式**：按照配方自动运行生产流程
  - **故障注入**：模拟传感器故障、通信中断等异常
- **技术实现：**
  - `QThread` + `QTimer` 驱动仿真循环
  - 仿真周期可配置（默认 100ms）
  - 模拟数据通过标签数据管道对外发布，与真实采集接口一致

### 6.3 数据点映射模型

一个统一的数据点（`Tag`）结构贯穿整个系统：

```cpp
// 数据点结构
struct TagDataPoint {
    std::string tag_name;        // 位号，如 "TE-101"
    std::string description;     // 描述
    std::string unit;            // 单位，如 "°C"
    DataType data_type;          // BOOL, INT16, UINT16, FLOAT, DOUBLE
    double raw_value;            // 原始值
    double scaled_value;         // 工程值
    uint8_t quality;             // 0=Bad, 64=Uncertain, 192=Good
    uint64_t timestamp_ms;       // 时间戳（毫秒）
    std::string source_device;   // 来源设备
};
```

### 6.4 Modbus 协议实现

**Modbus RTU（串口）：**

- 波特率：9600 / 19200 / 38400 / 115200
- 数据位：8
- 校验位：None / Even / Odd
- 停止位：1 / 2
- 支持的 Modbus 功能码：01、02、03、04、05、06、15、16
- 位号 → Modbus 地址映射表（可配置 JSON）

**Modbus TCP：**

- 默认端口：502
- 支持多设备连接池
- 自动重连机制（指数退避）

### 6.5 OPC UA 协议实现

**基于 open62541 的 OPC UA 客户端：**

- 匿名连接 / 用户名密码认证
- 浏览节点树
- 订阅（Subscription）方式订阅变量变化
- 读写节点属性
- 数据类型转换：OPC UA Variant → TagDataPoint

### 6.6 MQTT 协议实现

**基于 Eclipse Paho MQTT C++ 的客户端：**

- QoS 0 / 1 / 2
- Last Will 遗嘱消息
- 主题映射：`factory/reactor1/temperature`
- TLS 加密连接（可选）
- 数据上报格式：JSON

### 6.7 通信健康监控

```cpp
// 每个设备维护通信状态
struct DeviceHealth {
    bool connected;                 // 连接状态
    uint64_t last_comm_time;        // 最后通信时间
    uint32_t timeout_ms;            // 超时阈值
    uint32_t retry_count;           // 重试次数
    uint32_t max_retries;           // 最大重试
    uint32_t consecutive_failures;  // 连续失败
    DeviceStatus status;            // ONLINE / OFFLINE / FAULT
};
```

自动重连采用指数退避策略：1s → 2s → 4s → 8s → 16s 封顶。

## 附录：设计决策记录（ADR）

### ADR-001：Qt Widgets 还是 Qt Quick/QML

- **决策：** **Qt Widgets 为主，QML 为辅助**
- **理由：** Widgets 在上位机/SCADA 领域生态更成熟、自定义绘图更灵活（QPainter、QGraphicsView），学习曲线更适合过渡到企业工作；QML 可用于高动画需求的部分（工艺流程图动画）。

### ADR-002：QtSerialBus 还是 libmodbus

- **决策：** **QtSerialBus**
- **理由：** Qt 6 自带的 QModbusRtuSerialMaster 和 QModbusTcpClient API 更现代化、与 Qt 信号槽机制天然集成、不需要额外引入第三方库依赖。libmodbus 可在学习阶段作为对比理解。

### ADR-003：实时数据存储选择 SQLite 还是时序数据库

- **决策：** **SQLite（初期）→ 可替换为 InfluxDB/TimescaleDB（扩展期）**
- **理由：** SQLite 零配置、内嵌式、Qt6 原生 QtSql 支持，适合单机上位机的学习项目。

### ADR-004：工艺流程图使用 QGraphicsView 还是 QML Canvas

- **决策：** **QGraphicsView + 自定义 QGraphicsItem**
- **理由：** 交互编程更直观，信号槽集成更自然，适合面向对象设计模式的实践。
