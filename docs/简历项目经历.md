适合简历版面充足、投递 C++/Qt/工业软件方向岗位时使用。

**UCS 工业上位机监控系统（SCADA/HMI）** — 个人项目
**时间：** 2026.07 — 2026.12（按实际填写）
**技术栈：** C++17 · Qt 6.5（Widgets / Charts / SerialBus / Sql / GraphicsView）· CMake · vcpkg · SQLite · spdlog · Google Test

**项目描述：**
面向精细化工间歇式反应釜过程控制场景的工业上位机系统，覆盖"数据采集 → 实时监控 → 报警管理 → 历史追溯"完整数据链路。内置基于 FOPDT 一阶惯性模型的反应釜仿真引擎，模拟进料、加热、恒温反应、冷却、出料五个工艺阶段，无需真实 PLC 即可完整演示批次生产过程。

**主要工作与成果：**

- 设计并实现**四层架构**（表示层 / 业务逻辑层 / 数据层 / 通信层），通信层以抽象接口 `ICommunicationPort` 隔离协议差异，基于策略模式支持 Modbus RTU / TCP、OPC UA、MQTT 及仿真数据源的灵活切换，新增协议仅需实现接口即可接入

- 实现**线程安全的实时数据库（RTDB）**：环形缓冲区（RingBuffer）+ 哈希表管理 200+ 测点数据，`std::mutex` + `std::lock_guard`（RAII）保证通信线程与 UI 线程并发读写安全；采用 Qt 信号槽观察者模式推送数据变更，支撑 100ms 采集周期下的稳定运行

- 基于 **QtSerialBus** 实现 Modbus RTU/TCP 主站通信，封装"位号 → 寄存器地址"映射管理、批量轮询、超时重试与指数退避断线重连机制

- 使用 **QPainter 自绘**圆形仪表盘（带刻度 / 报警红区 / 指针）、LED 状态灯（报警闪烁）、液位柱等工业控件；通过坐标系标准化（translate + scale）实现控件任意尺寸下不变形

- 基于 **QGraphicsView 框架**实现 P&ID 工艺流程图：自定义反应釜、阀门、管道、泵等图元（QGraphicsItem），实现液位实时填充、阀门开关变色、管道虚线偏移流动动画、泵旋转动画，支持滚轮缩放与拖拽平移

- 采用 **QtCharts** 实现实时 / 历史趋势曲线，通过 `series->replace()` 批量替换与 Y 轴自适应缩放优化刷新性能，单曲线 600 数据点流畅渲染

- 基于 **SQLite** 实现历史数据持久化：按月分表、WAL 读写并发模式、事务批量写入（50 条/批）、死区压缩（变化超 2% 才存储），兼顾存储效率与查询性能

- 实现 **RBAC 三级权限模型**（操作员 / 工程师 / 管理员），采用 uint64 位掩码表示权限组合，支持操作审计日志记录

- 工程化实践：CMake Presets 统一 Debug/Release 构建配置，vcpkg manifest 声明式管理第三方依赖，spdlog 异步日志（控制台 + 滚动文件双 sink），Google Test 覆盖核心数据模块单元测试（TagManager / RingBuffer / HistoryDB 等）

## 四、面试应答要点（STAR 准备）

面试官大概率会围绕以下问题深挖，按此准备能让你从容应对。

### Q1：介绍一下这个项目？

**回答思路（30 秒电梯陈述）：**
> "这是一个模拟化工反应釜过程控制的工业上位机系统。核心是一个线程安全的实时数据库，向上支撑仪表盘、工艺流程图、趋势曲线等界面，向下通过抽象接口对接 Modbus、OPC UA 等工业协议。因为学习阶段没有真实 PLC，我写了一个基于一阶惯性模型的仿真引擎模拟完整的批次生产过程，让系统在没有硬件的情况下也能完整运行。"

**要点：** 先讲业务场景，再讲技术核心，最后讲工程亮点。不要一上来就罗列技术名词。

### Q2：实时数据库是怎么设计的？为什么用环形缓冲区？

**回答要点：**
- 数据结构：哈希表（位号→最新值）+ 每个测点一个 RingBuffer（历史 600 点）
- 为什么环形缓冲：固定容量、无内存重新分配、O(1) 插入、新数据自动覆盖最旧数据。实时趋势只需要最近 60 秒数据，用 vector 会一直膨胀
- 线程安全：互斥锁保护，注意 emit 信号放在锁外防止死锁（锁内槽函数若再调 RTDB 接口会自锁）

### Q3：多线程怎么处理的？遇到过数据竞争吗？

**回答要点：**
- 采集线程写 RTDB，UI 线程读 RTDB，用 `std::mutex` + `lock_guard` 保护共享数据
- 锁的粒度控制在最小范围（只锁数据读写段，不锁信号发送）
- 提到锁外 emit 信号防死锁的具体案例（能体现你踩过坑并解决了）

### Q4：为什么通信层要做抽象接口？

**回答要点：**
- Modbus、OPC UA、MQTT、仿真引擎对上层来说都是"数据源"
- 没有抽象层：UI 直接调 Modbus API，换协议要改界面代码
- 有抽象层：UI 只依赖 `ICommunicationPort`，新增协议只需实现接口、注册到 CommManager
- 这是策略模式 + 依赖倒置原则的实际应用

### Q5：Qt 信号槽你理解多深？

**回答要点：**
- 本质是观察者模式，松耦合
- 五种连接类型（Auto/Direct/Queued/BlockingQueued/Unique），跨线程默认 QueuedConnection
- Q_OBJECT 宏与 MOC 元对象编译器的作用
- 本项目应用：RTDB 值变更通知 UI、用户登录状态变更通知主窗口

### Q6：历史数据为什么选 SQLite？性能怎么保证？

**回答要点：**
- 选型：单机上位机不需要数据库服务器；Qt 内置驱动零依赖
- 性能优化四件套：按月分表（删旧数据直接 DROP TABLE）、WAL 模式（读写并发）、事务批量写入（50 条/批，写入提速约两个数量级）、死区压缩（变化 <2% 不存，平稳期数据量减少 90%+）
- 局限也清楚：多客户端并发写入不行，那种场景上 MySQL/TimescaleDB

### Q7：QGraphicsView 工艺流程图怎么实现的？

**回答要点：**
- 三层结构：Scene 管图元、View 管显示、Item 管自己怎么画
- 每个设备是 QGraphicsItem 子类，实现 boundingRect + paint 契约
- 动画实现：管道用画笔虚线偏移（dashOffset）模拟流动、泵用坐标系旋转、液位用 clipRect 裁剪防溢出
- 性能优化：DeviceCoordinateCache 缓存位图、状态没变不调用 update()

### Q8：这个项目最难的地方是什么？

**可选素材（挑你真实遇到的）：**
- 指针绘制时角度换算（Qt drawArc 角度单位是 1/16 度，0° 在 3 点钟方向）
- 环形缓冲区满态时"最旧元素定位"的下标计算
- 趋势曲线大数据量卡顿 → 从逐点 append 改为 replace 批量替换
- 历史库写盘卡 UI → 事务批量写入解决

**关键：** 一定要说"怎么解决的"和"学到什么"，不要只说困难本身。

### Q9：单元测试怎么做的？

**回答要点：**
- Google Test 框架，TEST_F 夹具共享初始化
- 覆盖核心数据模块：TagManager（JSON 加载/查找/去重）、RingBuffer（顺序/溢出覆盖/大容量）、HistoryDB（建库/CSV 导出）
- CTest 集成到构建流程，cmake 构建后一键运行

### Q10：如果让你继续做，下一步做什么？

**参考回答方向：**
- OPC UA 客户端完整接入（open62541），支持订阅模式
- 报警引擎完善：变化率报警、报警优先级队列、声音提示
- 配方管理：多阶段配方编辑与下发执行
- 性能：5000 测点规模下的压力测试与优化（读写分离、批量订阅）
- 跨平台：Linux 部署（Qt 天然支持，CMake 已具备条件）

## 五、简历填写建议

1. **项目时间**：建议跨度 3-6 个月，太短显得仓促，太长与个人项目定位不符。

2. **诚实边界**：标为"个人项目"没问题，面试官更看重你能否讲清每个技术决策的原因。仿真数据这件事不要包装成"对接了真实产线设备"，一说细节就露馅；相反，"为脱离硬件依赖自研仿真引擎"反而是加分项。

3. **量化数字来自真实实现**：200+ 测点、100ms 周期、600 点环形缓冲、50 条/批事务——这些数字必须和你的代码一致，面试被追问时打开代码能对上。

4. **准备好 Demo**：面试时可以现场或视频展示：启动程序 → 仿真批次自动运行 → 仪表盘/流程图/趋势联动。这比任何描述都有说服力。

5. **Git 提交历史**：如果开源到 Gitee/GitHub，保持提交记录的真实连续性，面试官可能会看。不要一次性提交所有代码。

6. **技能栈呼应**：简历"技能清单"部分提到的 C++17、Qt、Modbus、SQLite、CMake，都要能在这个项目里找到对应代码，形成"证据链"。
